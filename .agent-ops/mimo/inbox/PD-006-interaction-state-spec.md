文档要求：
1. 文档标题使用 `# 交互状态规格 PD-006`。
2. 必须在开头标注：`版本性质：假设版 / 待研究验证版`。
3. 必须包含以下章节：
   - 文档目的

   - 状态总览
   - 创建向导状态机
   - 状态规格明细
   - 表单校验与错误状态
   - 按钮与控件状态
   - 弹窗关闭与未保存内容处理

   - 创建成功与进入看板状态

4. 必须使用状态编号，建议格式：
   - `S01` 创建向导弹窗默认态
   - `S02` 创建方式选择态
   - `S03` 模板列表默认态
   - `S04` 模板列表选中态
   - `S05` 模板预览态
   - `S06` 空白项目输入态
   - `S07` 项目名称必填错误态
   - `S08` 提交中 / 创建中状态
   - `S09` 创建成功态
   - `S10` 取消创建 / 关闭弹窗态
   - `S11` 未保存内容关闭确认态
   - `S12` 移动端模板列表态
   - `S13` 移动端模板预览滚动态
   - `S14` 示例卡编辑态
   - `S15` 示例卡删除确认态
   可根据上游文档补充，但不得扩展到系统级功能。
5. 每个状态规格必须包含：
   - 状态编号
   - 状态名称
   - 来源依据（引用 PD-003 / PD-004 / PD-005 中的需求或状态）
   - 触发条件
   - 界面表现
   - 主要操作
   - 次要操作
   - 禁用 / 不可用操作
   - 状态退出条件
   - 下一个可能状态
   - 文案与错误提示
   - 移动端规则（如不适用需写明）
   - 验收标准（Given / When / Then）
   - 待验证点
6. 必须覆盖以下交互状态：
   - 默认态
   - 选中态
   - hover / focus / active 态（按钮、卡片、输入框如适用）
   - disabled 态
   - loading / submitting 态
   - empty 态（如模板预览无示例卡，需标注当前版本不涉及或未来扩展）
   - error 态
   - success 态
   - confirmation 态
   - mobile / responsive 态
7. 必须使用 Mermaid 绘制至少 3 张图：
   - 创建向导总状态机（建议 `stateDiagram-v2`）
   - 创建方式切换与提交校验状态转换图
   - 弹窗关闭 / 未保存内容确认状态图
   可额外补充移动端状态图或示例卡编辑/删除状态图。
8. 必须包含一个状态覆盖矩阵，横轴建议为：
   - 桌面端
   - 移动端 390px
   - 键盘操作
   - 错误处理
   - 关闭 / 取消
   - 研究待验证
9. 必须明确以下待验证决策，不得写成最终定论：

   - 轻提示自动消失时长是否合理
   - 预览内容是否足够帮助用户判断模板
   - 老用户是否会被模板入口干扰
   - 移动端创建向导是否足够可用
