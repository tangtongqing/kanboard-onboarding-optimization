文档要求：
1. 文档标题使用 `# 设计原则与非目标 PD-007`。
2. 必须在开头标注：`版本性质：假设版 / 待研究验证版`。
3. 必须包含以下章节：
   - 文档目的
   - 设计问题回顾
   - 设计原则总览
   - 设计原则详解
   - 原则到需求 / 状态的追踪
   - 范围边界
   - 非目标 Non-Goals
   - 决策取舍规则
   - 待研究验证的原则与边界
   - 后续进入 PD-008 / PD-009 / PD-010 的输入
4. 设计原则必须至少覆盖以下方向，并可根据上游文档合并命名：
   - 低干扰新手桥梁
   - 在做中教，而不是先教再做
   - 场景驱动，而非功能驱动
   - 保留高级用户效率
   - 可删除、可修改、可放弃
   - 假设可验证，而非直接定论
   - 静态作品集边界优先，避免继续功能膨胀
5. 每条设计原则必须包含：
   - 原则编号
   - 原则名称
   - 一句话定义
   - 来源依据（引用 PD-001~PD-006 或 V0.2 / V0.5）
   - 解决的问题
   - 设计含义
   - 应该做
   - 不应该做
   - 适用场景
   - 对后续线框 / 高保真 / 测试的影响
   - 待验证点
6. 非目标 Non-Goals 必须分层整理，至少包括：
   - 本轮 P0 不做
   - 后续 P1/P2 可能做但当前不做
   - 明确不属于本项目主线
   - 静态原型限制导致不做
   - 已有抢跑实现但不继续扩展
7. 非目标表格必须包含：
   - 非目标编号
   - 不做内容
   - 所属层级
   - 不做原因
   - 如果误做会带来的风险
   - 未来是否可能重新评估
   - 依据来源
8. 决策取舍规则必须覆盖：
   - 新手引导 vs 老用户效率
   - 模板丰富度 vs 创建流程轻量
   - 教学说明 vs 操作负担
   - 静态作品集表达 vs 真实产品完整性
   - 当前验证范围 vs 后续功能扩展
   - 已实现能力 vs 当前 PRD 范围
9. 必须使用 Mermaid 绘制至少 3 张图：
   - 设计原则追踪图：从问题 → 原则 → 需求 / 状态
   - 范围边界图：In Scope / Later / Out of Scope / Static Prototype Constraint
   - 决策取舍树：遇到新需求或设计分歧时如何判断是否纳入
   可额外补充 Non-Goals 分层图或原则优先级图。
10. 必须明确以下内容仍是 `[待验证]`，不得写成最终定论：
   - 默认选中「从模板开始」是否合适
   - 4 个模板是否覆盖目标用户核心场景
   - 模板预览是否足够帮助判断
   - 创建后轻提示是否必要
   - 老用户是否被模板入口干扰
   - 移动端创建向导是否足够可用
   - 示例卡是否能帮助用户理解任务粒度
11. 必须把“继续堆系统级功能不是当前主线”写成明确原则或边界，并解释原因。
