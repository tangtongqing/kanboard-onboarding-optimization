## 3. 关键内容说明

### 文档结构

文档包含 10 个章节，覆盖任务要求的所有必填项：

1. **研究目标**：5 个核心研究问题 + 5 个待验证假设（来自 PD-001 §6）
2. **当前已知假设**：6 个假设及置信度，明确标注桌面研究来源
3. **研究对象与招募条件**：3 组用户（学生/学习者 2-3 人、个人开发者 2-3 人、轻量团队负责人 1-2 人），含招募筛选标准和招募话术模板
4. **研究方法**：选择小样本可用性测试 + 半结构化访谈（5-8 人），说明了不采用大规模 A/B 测试等方法的理由
5. **访谈提纲**：开场（3 分钟）→ 背景了解（5 分钟）→ 可用性测试（15-20 分钟）→ 回顾访谈（10 分钟）→ 结束（2 分钟）
6. **可用性测试任务**：3 条路径——路径 A 空白创建（10 分钟）、路径 B 模板创建（10 分钟）、路径 C 老用户空白创建（5 分钟，可选），每条路径含详细观察点
7. **观察指标与记录表**：10 个观察指标（M1-M10）+ 两张可直接使用的记录表模板（可用性测试记录表、访谈记录表）
8. **结果分析方法**：定量分析（完成率、耗时对比、卡住频率、帮助度评分）+ 定性分析（卡住点归类、行为路径还原、用户原话提取、设计原则验证）
9. **研究边界与伦理**：5 个研究边界（样本量、用户类型、原型限制、执行环境、研究者偏差）+ 5 个伦理事项（知情同意、隐私保护、自愿退出、结果使用、感谢回馈）+ 知情同意话术
10. **输出物与后续衔接**：5 个输出物 + 如何进入 PD-003 PRD 的步骤 + 无法执行真实研究时的 4 个替代方案

### 关键设计决策

| 决策 | 理由 |
|---|---|
| 选择可用性测试而非 A/B 测试 | 静态原型无法支撑大规模 A/B 测试；学习实战项目资源有限 |
| 测试与访谈合并执行 | 节约参与者时间，一次测试同时获取行为数据和态度数据 |
| 覆盖 3 条测试路径 | 路径 A（空白）和路径 B（模板）是核心对比；路径 C（老用户）验证非目标假设 |
| 提供替代方案 | 考虑到学习实战项目可能无法执行真实研究，提供了桌面研究增强、专家评审、自我测试等替代路径 |
| 明确研究局限性 | 样本量小、静态原型、研究者偏差等边界都明确声明，避免过度推断 |

## 5. 未解决问题

1. **样本量不足风险**：5-8 人的样本量可能无法覆盖所有典型行为模式，特别是轻量团队负责人（C 组）可能只招到 1-2 人。
2. **远程测试的观察质量**：如果采用远程测试，可能无法观察到用户的微表情和肢体语言，影响对"卡住"程度的判断。
3. **静态原型的投入度**：用户面对静态原型可能不会像面对真实产品那样投入，影响行为数据的真实性。
4. **研究者偏差**：设计者同时是研究者，可能在提问和观察中无意识地引导用户。

## 6. 风险或需要 Codex 判断的点

1. **是否需要执行真实研究**：本计划提供了完整的研究方案，但执行需要时间和人力资源。Codex 需要判断：是先执行研究再进入 PRD，还是跳过研究直接基于假设写 PRD（在 PRD 中声明假设未验证）。
2. **替代方案的选择**：如果无法执行真实研究，应该选择哪个替代方案？桌面研究增强、专家评审、还是自我测试？不同替代方案对 PRD 的证据强度不同。
3. **研究结论的置信度**：即使执行了研究，5-8 人的小样本结论也不能当作统计显著的结论。PRD 中应该如何表述研究结论的置信度？
4. **与 PD-003 的衔接时机**：是否需要等研究执行完成才能进入 PD-003 PRD？还是可以先写 PRD 骨架，研究结论回来后再补充验证部分？
