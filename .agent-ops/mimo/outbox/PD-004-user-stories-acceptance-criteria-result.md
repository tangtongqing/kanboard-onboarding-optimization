## 3. 关键内容说明

### 文档结构

文档包含 8 个章节，覆盖任务要求的所有必填项：

1. **文档目的**：明确用户故事的定位和用途
2. **故事地图 Story Map**：可视化用户行为路径和故事层级关系
3. **P0 用户故事**：8 条（US001-US008），覆盖模板创建、预览、创建后跳转、修改/删除示例卡、空白创建、必填错误、移动端适配
4. **P1 用户故事**：3 条（US009-US011），覆盖字段微文案、创建后轻提示、保存自定义模板
5. **P2 用户故事**：1 条（US012），覆盖模板管理页
6. **跨故事验收规则**：8 条通用规则（加载时间、移动端、弹窗行为、校验时机等）
7. **待研究验证的验收点**：10 个需要 PD-002 研究执行后更新的验收点
8. **后续输入**：9 个流程节点 + 4 项需要研究后补充的内容

### 关键设计决策

| 决策 | 理由 |
|---|---|
| 12 条用户故事 | P0 8 条 + P1 3 条 + P2 1 条，覆盖 PRD 中所有需求 |
| Given/When/Then 格式 | 验收标准可直接转为 BDD 测试用例 |
| 10 个待验证点 | 明确标注需要 PD-002 研究执行后更新的内容 |
| 跨故事验收规则 | 覆盖加载时间、移动端、弹窗行为等通用质量要求 |
| 故事地图 | 可视化用户行为路径，帮助理解故事之间的依赖关系 |

## 5. 未解决问题

1. **示例卡具体内容**：US004 和 US005 定义了修改/删除示例卡的行为，但没有给出每个模板的具体示例卡标题和描述。这需要在后续设计阶段确定。
2. **轻提示的触发条件**：US010 定义了创建后轻提示，但"第一次"的判断条件需要明确（是按用户维度还是按项目维度）。
3. **自定义模板的数据结构**：US011 定义了保存自定义模板，但模板的数据结构需要与现有 localStorage 数据结构兼容。

## 6. 风险或需要 Codex 判断的点

1. **验收标准的测试可行性**：Given/When/Then 格式的验收标准可以直接转为 BDD 测试用例，但当前静态原型的测试脚本是 Playwright 脚本，不是 BDD 框架。Codex 需要判断：是否需要在后续开发中引入 BDD 测试框架。
2. **P0 故事的完整性**：当前 P0 故事覆盖了任务要求的所有场景，但某些细节（如模板切换动画、预览区滚动行为）没有展开。Codex 需要判断：这些细节是留给 PD-006 交互状态规格，还是需要在用户故事中补充。
3. **待验证点的数量**：10 个待验证点覆盖了主要假设，但可能还有遗漏。Codex 需要判断：是否需要在 PD-002 研究执行前补充更多待验证点。
