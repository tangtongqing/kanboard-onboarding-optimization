## 10. PD-011 Gate 结论

### 结论：**Conditional Go**

规则应用：
- P0 = 0，不触发 No-Go
- 核心 P1（R06/R08/R11/R14）是规格-实现矛盾，但**均有明确低风险暂定方案**，不触发 No-Go
- V03~V06 均有可执行 PD-011 输入
- **无真实用户数据**，按规则不得无条件 `Go`

### Conditional Go 的 7 项条件（PD-011 启动前必须满足）

1. 修复 R06（S07 必填错误 + aria）
2. 修复 R08（移动端底部 sticky）
3. 修复 R11（示例卡 isExample + 徽标）
4. 修复 R14（S11 关闭确认）
5. 修订 PD-006（消除 V05 矛盾）
6. V03~V06 作为暂定输入进 PD-011，全保留 `[待真人验证]`
7. 真人形成性测试与 PD-011 并行；V03~V06 定稿、R 严重度校准等真人结论

任一条件未满足，Gate 回退 No-Go。

## 13. 风险或需要 Codex 判断的点

1. **规格-实现矛盾优先级**：R06/R08/R11/R14 是本走查最可靠发现，建议 Codex 优先下发修复任务（而非等真人验证），因为它们是"规格要求了但代码没做"，与用户行为无关，属工程欠债。
2. **V05 矛盾处理**：PD-006 描述（名称在方式内）与代码（名称在方式上）矛盾。建议 Codex 决定：修订 PD-006 对齐代码（成本低），还是改代码对齐 PD-006（成本高、影响老用户）。主文档暂定前者。
3. **R06 取舍**：PD-010 验收记录称"名称为空时允许提交并触发 S07"，但现有代码是"名称为空静默 return"。需 Codex 确认最终行为，以免修复方向与验收记录冲突。
4. **Conditional Go 是否接受**：7 项条件中，R06/R08/R11/R14 修复 + PD-006 修订属"必须"，V03~V06 暂定 + 真人并行属"流程"。Codex 可决定是否要求部分条件在 PD-011 前完成、部分并行。
5. **真人测试可行性**：5-8 人招募依赖用户个人社交圈（PD-002 §4），若无法招募，需 Codex 决定是否接受"桌面研究增强 + 自我走查"替代（PD-002 §10），此时 V03~V06 将长期保持暂定。
6. **Mermaid 渲染**：E03 Gate 决策树含多分支与长中文标签，Codex 导出 PNG/SVG 时需目视检查文字裁切与分支可读性。
7. **PD-011 启动口径**：本 Gate 是 Conditional Go，但 PD-011 高保真是大投入。建议 Codex 在下发 PD-011 前，至少先完成 R06/R08/R11/R14 修复任务并验收，避免高保真建立在有缺陷的代码基线上。
