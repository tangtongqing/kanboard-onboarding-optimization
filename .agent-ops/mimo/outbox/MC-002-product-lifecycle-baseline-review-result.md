## 1. 复核摘要

从完整产品生命周期角度复核，`docs/00-project-governance/产品生命周期真实进度基线.md` 的核心判断**基本准确**：项目存在"静态实现进度"远超"产品设计产物进度"的结构性偏差。文档准确识别了 PRD、用户故事、信息架构、流程图、可用性测试等关键产物的缺失，并正确建议暂停 V0.8.28 功能复现。

但文档在以下方面存在遗漏或可以进一步精确化：
- 对 V0.5 新手创建向导的完成度评价偏低，实际上它已包含可运行的 Mermaid 流程图、模板结构设计和验证记录，不应仅标为"部分完成"。
- 对"用户旅程"的完成度判断需要细分：用户旅程地图已存在于 `docs/01-research-discovery/用户研究与需求池-V0.2.md` 中，只是缺少优化前后的对比路径。
- 缺少对"作品集叙事"的前置依赖分析——作品集叙事需要高保真原型，而高保真原型需要信息架构和流程图，不应直接跳到 P2。

## 7. 是否暂停 V0.8.28 的判断

**建议暂停 V0.8.28，默认主线切换为 P0 产品设计补齐。**

理由：

1. **范围偏离**：V0.8.28 计划继续核对 Admin/Settings、数据库配置、安全配置或剩余 API procedures。这些内容属于 Kanboard 实例级运维能力，与"新手项目创建与任务拆解优化"的核心命题关联度低。
2. **边际价值递减**：从 V0.8.19 到 V0.8.27，每个版本都在补齐系统级能力（认证、运维、运行环境、部署、插件、API），静态原型已覆盖 Kanboard 大部分用户侧和管理侧可见功能。继续堆功能的边际价值已明显低于补齐 PRD、用户故事和流程图。
3. **作品集需要设计产物**：作品集评审看的是"发现问题→分析问题→设计方案→验证方案"的完整链路，而不是"实现了多少页面"。当前实现资产已足够支撑高保真原型，缺少的是设计决策的文档化表达。
4. **已有 V0.5 新手创建向导**：核心优化方案（模板创建向导）已在 V0.5 实现并验证，后续应该围绕这个方案补齐 PRD 和用户故事，而不是继续扩大 Kanboard 复现范围。

**例外情况**：如果在 PRD 编写过程中发现某个系统级能力是新手创建向导的前置条件（例如：模板需要保存为自定义模板，涉及后端存储），可以作为临时任务补充，但不应成为默认主线。

## 9. 未解决问题

1. **访谈可行性**：PD-002 用户研究计划中，是否需要真实招募访谈对象？如果项目定位为"学习实战"而非"真实产品上线"，桌面研究 + 可用性测试（找同学试用）是否足够？
2. **PRD 粒度**：PD-003 PRD 骨架应该写到什么程度？是完整的产品需求文档，还是聚焦"新手创建向导"这一个功能点的精简 PRD？
3. **Figma 是否必须**：V0.9 计划进入 Figma 高保真原型，但当前静态原型已有较高交互完成度。是否可以用静态原型直接作为作品集展示，跳过 Figma？
4. **静态原型的定位**：当前 335 项检查通过的静态原型，在作品集中应该被定位为"可交互原型"还是"开发实现"？这会影响作品集叙事结构。

## 10. 风险或需要 Codex 判断的点

1. **功能复现惯性风险**：项目已形成"每个版本补齐一批 Kanboard 功能"的工作惯性。暂停 V0.8.28 后，需要明确新的工作节奏，避免在 P0-P2 补齐过程中又回到功能复现。
2. **PRD 与实现倒挂风险**：当前实现已远超 PRD 定义范围。补齐 PRD 时需要决定：是 PRD 描述现有实现，还是 PRD 定义理想方案然后评估实现差距？建议选择后者，因为 PRD 应该是设计决策的记录，不是实现的文档化。
3. **作品集时间风险**：如果 P0-P2 全部补齐，工作量可能超过继续功能复现。需要评估距离作品集提交的剩余时间，决定 P0-P2 的深度和取舍。
4. **V0.5 定位争议**：基线文档可能被认为低估了 V0.5 的完成度。V0.5 已包含完整的创建向导流程图、4 个模板结构设计和浏览器自动化验证，这应该被视为"产品设计产物"而非仅是"实现"。
