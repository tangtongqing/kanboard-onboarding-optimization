## 2. 关键修复

### 产品移动端

- 根因是后置重复媒体查询将 `.view-controls` 从单列覆盖为两列。
- 390px 下显示控制已改为单列，卡片显示和隐藏空列控件宽度均为 `336px`。
- 视图按钮触控高度不低于 `44px`，页面无横向溢出。

### 产品真实性与联系闭环

- 未配置私密端点时，联系内容会先在浏览器本地整理，再由用户主动打开当前项目的 GitHub Issue。
- 配置 `KANBOARD_CONTACT_ENDPOINT` 后，页面会显示邮箱字段，并通过 HTTPS JSON POST 提交到私密接收端。
- 私密提交成功后不展示公开 Issue 按钮；提交失败时保留原表单并允许重试。
- 失败降级生成的公开 Issue 永远不包含邮箱，页面也会提醒用户移除敏感信息。
- 构建会拒绝非 HTTPS 端点，并在写入内联脚本前转义 HTML 特殊字符。

### 性能与无障碍

- 首屏标题和产品截图不再等待 GSAP reveal 动画。
- Google Fonts 改为非阻塞加载，字体字重从 10 个收敛到 6 个。
- 首屏图片增加固有尺寸和高优先级加载，非首屏图片增加懒加载。
- 修复图片 CSS 高度，避免声明尺寸后产生错误宽高比。
- 视图切换从错误的 `tablist + aria-selected` 改为 `group + aria-pressed`。
- 修复产品描述、视图按钮、营销深色区正文和案例页脚注对比度。

## 5. 发布结论

### 作品集和公开演示

通过。核心产品闭环、移动端主要操作、营销信息、价格切换、联系动作和设计证据均可使用。

### 正式商业化营销站

有条件通过。私密表单的前端、构建配置、成功/失败状态、蜜罐字段和安全降级均已完成；正式投放前需要在 GitHub 仓库变量中配置实际 HTTPS 接收端，并确认服务端具备限流、反垃圾、数据保留和隐私合规策略。

## 6. 私密咨询上线配置

1. 准备支持 HTTPS JSON POST 的表单端点，例如 Formspree 表单地址或自有 API。
2. 在 GitHub 仓库的 Actions 变量中创建 `KANBOARD_CONTACT_ENDPOINT`。
3. 将变量值设为完整 HTTPS 地址，不要填写 API 密钥或管理令牌。
4. 重新运行 `Deploy GitHub Pages` 工作流。
5. 在线验证成功提交、服务端拒绝、超时重试和公开降级四条路径。

未配置变量时，构建会写入空端点，网站继续使用不含邮箱的公开 Issue 路径，不会伪装成私密提交。

### 产品能力边界

当前仍是浏览器本地交互原型。账号、云同步、多人协作、邮件、插件安装、API 和部署等能力属于方案展示或本地模拟，不能对外宣称为已经连接真实后端的生产能力。
