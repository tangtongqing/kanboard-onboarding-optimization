## B. 10 页作品集打印内容

### 第 1 页：项目背景与冷启动困境
* **页面标题**：空白看板与新手用户的冷启动困境
* **副标题**：功能完整性与用户上手阻力之间的断层
* **页面核心信息**：工具强大但界面空白，让新手用户面临结构困惑与操作焦虑，导致流失率高。
* **正文要点**：
  * • 空白项目路径：创建项目后无默认列与泳道，用户不知道如何将目标拆解为执行步骤。
  * • 示例卡操作焦虑：用户面对系统生成的说明示例卡不敢编辑或删除，怕破坏原有系统设置。
  * • 核心切入点：将上手体验重构为“创建前引导结构预测”、“创建后探索动作激发”及“操作时低干扰防御”。
* **建议视觉资产**：空白项目看板图（见 `设计图/PD-018D/01-project-list-with-checklist-button.png`）
* **口播提示**：Kanboard 拥有强大的看板管理能力，但当新手创建项目后，面对一个光秃秃的空白看板，会产生极高的“起步成本”与操作焦虑。这并非按钮找不到的问题，而是激活路径上的断层。
* **风险边界**：此困境基于 GitHub Issues 和 Hacker News 上的真实新手 complaints 整理，不宣称实施了招募式真人测试。

### 第 2 页：研究证据与项目边界
* **页面标题**：公开案例证据驱动与主动的边界声明
* **副标题**：用严谨的二手研究与专家走查为设计基准提供依据
* **页面核心信息**：通过公开社区案例研究和专家路径走查，明确核心流失原因并坦诚项目限制。
* **正文要点**：
  * • 数据基础：提取官方文档、GitHub Issue 及 Hacker News 的公开案例，避免个别样本偏差。
  * • 核心发现：新手的痛点是“第一根列和泳道到底该叫什么名字”，而非寻找基础交互按钮。
  * • 主动边界：项目无招募式真人测试，移动端适配以 Chromium 390px 视口仿真进行，边界透明。
* **建议视觉资产**：二手研究证据总结图（见 `docs/05-validation/公开用户证据研究与模拟走查-PD-010D-R.md`）
* **口播提示**：在研究阶段，我主动为这个项目设立了清晰的边界：不进行招募式测试，而是通过分析 GitHub Issues 和官方论坛的新手痛点，结合专家走查，建立二手研究基准。诚实面对限制能让我们聚焦在最真实的问题上。
* **风险边界**：不宣称“调研了 X 名真实用户”或“完成了可用性测试”。

### 第 3 页：设计目标与非目标
* **页面标题**：轻量级设计干预与高级路径保护
* **副标题**：克制的设计原则比一味做加法更有价值
* **页面核心信息**：设计低干扰的引导体验以激活新手，同时绝对隔离高级用户，避免效率降级。
* **正文要点**：
  * • 新手激活：通过场景模板快速起步，通过 0/3 激活 Checklist 驱动探索核心操作。
  * • 操作防御：通过首次拖拽/编辑/删除等节点的轻量 Popover，消除破坏性焦虑。
  * • 核心非目标：高级用户空白路径完全隔离；不破坏现有数据结构，不引入注册或收费系统。
* **建议视觉资产**：设计原则与非目标思维导图（见 `docs/03-ux-design/设计原则与非目标-PD-007.md`）
* **口播提示**：我们最核心的原则是克制。我们在设计新手引导的同时，设计了刚性的隔离路径——如果高级用户不选择模板，他们看到的看板将和过去完全一样，没有任何引导打扰他们的工作效率。
* **风险边界**：不涉及任何商业上线或运营转化指标。

### 第 4 页：创建前——结构化模板与示例卡
* **页面标题**：场景模板：看板结构的初始化起点
* **副标题**：4 种高频工作流模板与实时可视化预览
* **页面核心信息**：提供“学习计划”、“冲刺追踪”等 4 种模板，配合预览及可编辑示例卡，降低起步摩擦。
* **正文要点**：
  * • 实时可视化：模板选择区提供列、泳道及示例卡数量的直观预览，建前感知。
  * • 可编辑示例卡：示例卡自带“完成标准”、“避坑提醒”指引，双击即可修改卡片标题。
  * • 熟练用户防护：第一项依旧为“空白模板”，允许资深用户一键跳过结构化配置。
* **建议视觉资产**：模板创建弹窗预览图（见 `设计图/PD-018D/03-template-selection-modal.png`）
* **口播提示**：我把示例卡定义为“真实任务”而不是“说明书”。它包含完成标准与避坑提示，但用户双击就能将其改成自己的任务。这就通过实际动作，帮助用户完成了破冰的第一步。
* **风险边界**：Figma 原稿因环境 OAuth 写入权限阻塞，在此阶段高保真规格定义在本地。

### 第 5 页：创建后——新手激活 Checklist
* **页面标题**：挑战驱动：让新手用动作完成激活
* **副标题**：0/3 到 3/3 核心行为引导与容错退场机制
* **页面核心信息**：使用右下角 Checklist 引导 3 类最核心的看板交互，状态按项目 ID 隔离并持久化。
* **正文要点**：
  * • 三项挑战：修改示例卡标题、拖拽任务卡到下一列、在首列新建卡片，完成即消失。
  * • 容错逻辑：若用户直接删除了示例卡，挑战一自动fallback为“双击创建并保存卡片”。
  * • 移动端适配：折叠为圆形进度气泡，点击从底部唤出半高滑盖面板（Bottom Drawer）。
* **建议视觉资产**：右下角 Checklist 渲染状态图（见 `设计图/PD-018D/` 相应回归截图）
* **口播提示**：这个 Checklist 的独特之处在于它有 Fallback 机制：如果新手由于焦虑把示例卡删光了，第一步“编辑卡片”会自动变成“新建并保存任意卡片”。我们确保用户即使有误操作，引导依然能带他走向成功。
* **风险边界**：Checklist 的数据均在本地存储，未接入任何后端数据库。

### 第 6 页：字段 Tooltip 与白话术语解释
* **页面标题**：消除专业壁垒，将字段白话化
* **副标题**：10 项高频名词大白话释义与定位智能避让
* **页面核心信息**：将“WIP 限制”、“泳道”等 10 个专业概念绑定帮助气泡，采用防溢出定位和互斥避让。
* **正文要点**：
  * • 大白话文案：将技术名词转为“本列卡片上限”或“横向隔离轨道”等大白话表述。
  * • 边缘检测：浮窗自适应屏幕边缘，自动翻转朝向，避免截断或溢出。
  * • 全局避让：当 Tooltip 打开时，Checklist 引导 Popover 会自动被抑制并进入 suppressed 状态。
* **建议视觉资产**：术语解释 Tooltip 气泡截图（见 `设计图/PD-018D/` 相应回归截图）
* **口播提示**：很多敏捷管理工具充斥着行业术语。我通过 10 个白话 Tooltip，把“WIP”解释为“本列可放卡片上限”。同时，当 Tooltip 展示时，引导会主动避让，确保用户专注理解概念。
* **风险边界**：无。

### 第 7 页：首次核心操作轻引导
* **页面标题**：首次行为触发的低干扰动态防御
* **副标题**：拖拽、编辑、删除等操作的首次 Popover 引导
* **页面核心信息**：只在用户首次执行相应交互时提供一次性引导，并配合对话框拦截和全局退场。
* **正文要点**：
  * • 拖拽 Popover：鼠标 hover 卡片超过 0.8s 自动唤起，用户开始 dragstart 后立即消失。
  * • 编辑与删除：用卡片旁的呼吸红点指示编辑，用温和的首次删除 Dialog 替代原生警告。
  * • 抑制机制：任何 Dialog 或 Tooltip 处于激活状态时，Popover 引导自动退场，防止界面过载。
* **建议视觉资产**：拖拽引导 Popover 截图（见 `设计图/PD-019D/` 相应回归截图）
* **口播提示**：最好的引导是“随用随现，用完即逝”。比如拖拽 Popover，只在卡片上悬停 0.8 秒才会出现，一旦开始拖拽就会永久消失。多层引导在弹出时互斥，不会让界面堆满弹窗。
* **风险边界**：轻引导为一次性全局状态，数据缓存于 LocalStorage。

### 第 8 页：390px 移动端布局与适配
* **页面标题**：移动端仿真：空间受限下的版面自适应
* **副标题**：基于 390px 宽视口下的引导替代方案
* **页面核心信息**：在移动端用 inline 提示条与 Bottom Sheet 代替气泡，保持界面可读与触控安全。
* **正文要点**：
  * • 空间替换：引导 Popover 替换为 32px 的 inline 提示条；Checklist 浮窗折叠为气泡。
  * • 触控优化：所有交互按钮及 Bottom Sheet 的操作高度均不低于 44px。
  * • 视口限制：适配验证在 Chromium 390px 视口中进行，不保证真机系统兼容性。
* **建议视觉资产**：移动端 inline 提示条截图（见 `设计图/PD-019D/10-mobile-390-inline-guidance.png`）
* **口播提示**：在 390px 移动视口下，屏幕空间不足以容纳复杂的浮窗。我把拖拽 Popover 降级为 32px 的 inline 提示，把删除 Dialog 变成了从底部滑出的 Bottom Sheet。每一个触控目标都保证了 44px 的高度。
* **风险边界**：⚠️ 必须老实说明无真实物理设备测试，移动端以 Chromium 390px 仿真视口为准。
