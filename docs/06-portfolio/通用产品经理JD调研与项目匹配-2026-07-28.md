## 2. 通用产品经理的核心职责

### 2.1 用户、市场与问题研究

- 研究目标用户、使用场景、行为和痛点；
- 进行市场、行业和竞品分析；
- 从业务需求、用户反馈和产品数据中识别机会；
- 区分表面需求与核心问题；
- 输出问题定义、用户场景和需求依据。

### 2.2 需求分析与产品规划

- 将模糊需求拆成具体功能、流程、规则和状态；
- 编写 PRD、用户故事、需求规格和验收标准；
- 设计版本范围、优先级和产品路线图；
- 平衡用户价值、业务目标、技术成本和交付风险；
- 明确 In Scope、Out of Scope 和依赖关系。

### 2.3 产品与交互设计

- 梳理业务流程、信息架构和数据对象；
- 使用 Figma、Axure、墨刀等工具制作原型；
- 定义页面、组件、错误、空状态、加载、权限和异常路径；
- 与 UI/UX 对齐视觉和交互方案；
- 确保方案能够被研发、设计和测试理解与执行。

### 2.4 项目推进与上线交付

- 组织或参与需求评审；
- 明确里程碑、任务、责任人、依赖和风险；
- 跟进设计、开发、联调、测试和缺陷修复；
- 根据验收标准完成 UAT 或产品验收；
- 推动版本发布并维护需求、版本和变更记录。

### 2.5 数据分析与持续迭代

- 定义核心指标、事件和数据口径；
- 分析功能使用率、转化、留存、满意度或业务指标；
- 收集并归类用户反馈；
- 基于数据和反馈形成迭代方案；
- 上线后复盘产品结果、问题与后续路线。

## 4. 推荐的合成目标 JD

以下为根据岗位样本整理的“产品助理 / 助理产品经理 / 初级产品经理”合成 JD，不对应某一家公司的原文。

### 岗位职责

1. 通过用户反馈、公开资料、行业与竞品研究，协助识别产品问题和高价值需求。
2. 梳理用户场景和业务流程，将需求拆解为功能、规则、状态和优先级，输出 PRD、用户故事、流程图及验收标准。
3. 使用 Figma、Axure 等工具完成原型和交互说明，覆盖正常、异常、加载、错误和移动端等关键状态。
4. 参与需求评审，跟进设计、开发和测试进度，协调解决需求理解、范围变更和验收问题。
5. 根据验收标准执行产品测试和缺陷跟踪，推动功能按计划上线。
6. 收集上线后的用户反馈和产品数据，分析问题并形成迭代建议。
7. 维护需求池、版本记录、产品说明和项目文档，保证信息完整、准确、可追溯。
8. 使用 AI 和自动化工具提升资料整理、原型、测试和日常交付效率，并对输出结果进行复核。

### 任职要求

1. 具备用户研究、需求分析、竞品分析和基础产品规划能力。
2. 能独立完成流程、原型、PRD、用户故事和验收标准。
3. 逻辑清晰，能够把模糊问题拆成可执行方案。
4. 具备良好的沟通、文档、进度跟踪和问题推动能力。
5. 对用户体验和数据敏感，理解常见产品指标和分析方法。
6. 了解前后端、接口、数据库、测试和发布等基础技术概念。
7. 自驱力和学习能力强，有产品实习、个人产品、比赛或完整作品集者优先。
8. 理解 AI 工具及能力边界，能将其用于产品工作提效者优先。

## 6. 岗位方向匹配

| 岗位方向 | 当前匹配度判断 | 原因 |
| --- | --- | --- |
| 产品助理 | 强 | 研究整理、PRD、原型、文档、测试、版本和执行证据完整 |
| 助理产品经理 / 初级产品经理 | 强 | 能展示问题定义、需求规划、交互设计和独立交付 |
| 工具/SaaS 产品经理 | 强 | 项目本身是工作流与看板工具，流程、状态和效率场景突出 |
| C 端体验产品经理 | 中高 | 有新手激活和移动端设计，但没有真实 C 端用户数据 |
| B 端产品经理 | 中 | 有复杂流程和平台理解，但缺少真实企业客户和业务流程 |
| 数据产品经理 | 中低 | 有指标设计，没有数据平台、SQL 和真实数据分析证据 |
| 产品运营 | 中 | 有激活和承接设计，没有真实运营活动和用户增长结果 |
| 商业产品经理 | 低 | 没有广告、电商、会员、收入或商业模型验证 |
| 增长产品经理 | 低 | 没有真实流量、实验和转化增长结果 |

## 7. 通用 PM 与 AI PM 的区别

| 维度 | 通用产品经理 | AI 产品经理 |
| --- | --- | --- |
| 基础问题 | 用户需要什么产品能力 | 哪些用户任务适合由 AI 完成 |
| 方案重点 | 功能、流程、规则、页面和业务逻辑 | Prompt、Workflow、Agent、RAG、工具和人工确认 |
| 验收重点 | 功能正确、流程可用、业务规则一致 | 模型效果、稳定性、时延、成本、安全和失败降级 |
| 数据重点 | 使用、转化、留存、效率或收入 | 任务成功率、准确性、模型行为与产品指标 |
| 当前项目匹配 | 强 | 部分匹配，缺真实 AI 功能 |

结论：

- 当前 Kanboard 项目应优先作为通用产品经理主投项目。
- AI 产品经理版本只能作为过渡版，突出 AI 工具应用和能力边界，不能声称 AI 产品实绩。
- 若后续补齐真实 AI 任务拆解助手及模型评测，再考虑把 AI 产品经理提升为主投方向。

## 8. 第二阶段重构建议

### 主投版本：通用产品经理

固定四条：

1. 用户研究与问题定义；
2. 需求分析与产品规划；
3. 产品方案与交互设计；
4. 项目推进与静态上线交付。

数字建议只保留两组：

- “4 个竞品/公开用户证据研究”用于研究与判断；
- “449 项自动化检查通过”用于交付与验收。

F01—F47、74 张 Figma PNG、26 张回归截图等数量放入作品集或面试补充，避免主简历被交付数量淹没。

### 备选版本：AI 应用产品经理过渡版

保持事实不变，只调整关键词顺序：

1. 用户场景与工作流分析；
2. 需求、流程和复杂状态规划；
3. 快速 Demo 与人机交互思维；
4. 验收体系、能力边界与 AI 辅助交付。

项目名称仍使用“Kanboard 新手激活与项目创建体验优化”，不增加“AI 产品”字样。
