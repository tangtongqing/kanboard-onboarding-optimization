## 1. 项目背景

Kanboard 是一款经典开源看板式项目管理工具，聚焦 Kanban 方法，产品形态轻量。本项目选择 Kanboard 作为优化对象，聚焦"新手项目创建与任务拆解体验优化"。

项目起源于一个观察：Kanboard 的优势是轻量，但对新手来说，"轻"也可能意味着缺少决策支持。新用户进入项目创建路径后，即使产品提供基础看板结构，也仍需要自己判断哪些列适合当前场景、应该写哪些任务、用什么粒度拆解。这可能导致新手从"我想管理任务"到"我有一张可用看板"的路径过长，首次成功体验不稳定。

本项目的目标是在保持 Kanboard 轻量定位的前提下，为新手提供一次"从目标到看板"的辅助创建过程，同时不打扰老用户的使用效率。

## 2. 产品机会一句话

**在 Kanboard 的新建项目流程中增加"从模板开始"的低干扰新手桥梁，让首次用户在 3 步内从场景选择进入可用看板，同时保留空白项目快速创建路径给老用户。**

## 3. 问题陈述 Problem Statement

### 用户问题

初次使用看板工具管理个人项目或小团队任务的用户（学生、个人开发者、轻量团队负责人），在第一次创建项目时可能不知道如何从模糊目标拆成可执行的任务列表。他们可能理解"看板"概念，但缺少从目标到列结构、从目标到任务粒度的具体拆解方法，导致首次创建耗时长、看板结构混乱、任务字段填写疑惑多。

### 问题影响

- 新用户首次项目创建完成率可能偏低，可能在配置看板阶段放弃。
- 即使完成创建，看板结构也可能不符合当前场景需要（列过多或过少、任务粒度不统一）。
- 字段含义（负责人、优先级、截止时间）缺少场景解释，用户不知道怎么填。
- 用户把工具当普通清单使用，没有理解看板流转的核心价值。

### 问题边界

本问题聚焦"新建项目到形成第一张可用看板"的关键路径，不涉及登录注册、多人实时协作、权限体系、API 集成等系统级能力。

## 4. 目标用户

### 用户A：作品集准备中的学生

| 维度 | 内容 |
|---|---|
| 背景 | 正在准备课程项目、竞赛或求职作品集 |
| 目标 | 把一个大项目拆成调研、方案、原型、复盘等任务 |
| 能力 | 有学习意愿，但项目管理经验弱 |
| 痛点 | 不知道第一张看板应该有哪些列，也不知道任务卡该写多细 |
| 价值点 | 用模板快速看到"一个项目应该怎么拆" |

### 用户B：个人开发者

| 维度 | 内容 |
|---|---|
| 背景 | 用自托管工具管理开源项目或个人产品 |
| 目标 | 管理需求、Bug、待办、发布计划 |
| 能力 | 技术能力强，但不一定愿意配置复杂工具 |
| 痛点 | 创建项目后还要手动建列、建分类、写示例任务，启动成本高 |
| 价值点 | 用 Bug 跟踪或小版本迭代模板快速开始 |

### 用户C：轻量团队负责人

| 维度 | 内容 |
|---|---|
| 背景 | 负责 2-5 人小团队的任务推进 |
| 目标 | 看清每个人的任务状态和阻塞点 |
| 能力 | 有协作需求，但不想引入复杂项目管理系统 |
| 痛点 | 不知道如何让团队统一任务状态和字段标准 |
| 价值点 | 用小团队迭代模板统一列、优先级、负责人和截止时间 |

## 5. 当前体验痛点

| 痛点 | 产生原因 | 影响 | 机会 |
|---|---|---|---|
| 面对空白项目无从下手 | 缺少场景化结构和示例 | 首次成功体验不稳定 | 模板创建 |
| 不知道任务该怎么拆 | 缺少任务粒度参考 | 看板很快变成杂乱待办 | 示例任务卡 |

## 7. 优化目标

### 核心目标

缩短新用户从"进入产品"到"拥有一张可用看板"的路径，降低空白项目带来的认知负担，让用户在第一次使用中理解 Kanboard 的基本工作流。

### 具体目标

1. 新用户首次项目创建完成率提升（通过测试对比空白路径和模板路径）。
2. 首次创建耗时下降（从"需要自行判断列和任务粒度"到"按场景模板 3 步完成"）。
3. 首次看板有效任务数提升（创建后用户能保留或新增真实任务，而不是删除所有示例卡）。
4. 模板使用率可观察（新项目中选择模板创建的比例）。
5. 不降低老用户的创建效率（空白创建路径保持原有快捷性）。

## 9. 设计原则

### 原则1：低干扰新手桥梁

在保持 Kanboard 轻量定位的前提下，为新手提供一次"从目标到看板"的辅助创建过程。新功能不应该让创建路径变重，老用户仍然可以选择"空白项目"，保留原有习惯。

**来源**：竞品分析结论（`docs/01-research-discovery/竞品分析报告-V0.2.md` §7）——"Kanboard 不需要变成 Trello 或 Notion。更合理的优化是：在保持轻量工具定位的前提下，为新手提供一次'从目标到看板'的辅助创建过程。"

### 原则2：在做中教，而不是先教再做

新手需要在实际操作中理解看板方法，而不是先阅读文档再开始使用。模板和示例卡本身就是教学工具，用户通过选择场景、查看列结构、修改示例卡来理解任务拆解方式。

**来源**：竞品分析启示（`docs/01-research-discovery/竞品分析报告-V0.2.md` §5）——"Trello 和 Notion 的共同做法是把'方法'包装进模板。用户不是先学习项目管理理论，再开始建看板，而是先选择一个场景模板，在示例列和示例卡片里理解任务拆解方式。"

### 原则3：场景驱动，而非功能驱动

模板按用户的真实使用场景组织（个人学习、求职准备、小团队迭代、Bug 跟踪），而不是按 Kanboard 的功能模块组织。用户选择的是"我要做什么"，而不是"我要用哪些功能"。

**来源**：用户研究场景定义（`docs/01-research-discovery/用户研究与需求池-V0.2.md` §3）——4 个核心场景都以用户目标为起点。

### 原则4：保留高级用户效率

空白创建路径必须保持原有快捷性，不能因为新手功能而增加老用户的操作步骤。新手功能和老用户功能应该共存，而不是互相干扰。

**来源**：竞品分析结论（`docs/01-research-discovery/竞品分析报告-V0.2.md` §5）——"高级用户效率：极简、直接...新方案必须保留空白项目快速创建。"

### 原则5：可删除、可修改、可放弃

示例卡、模板结构和列配置都应该是可删除、可修改的。用户不应该被模板绑定，而应该把模板作为起点，根据自己的需求调整。

**来源**：需求池定义（`docs/01-research-discovery/用户研究与需求池-V0.2.md` §7）——"示例卡必须可删除。"

## 10. 非目标 Non-Goals

以下内容不作为"新手项目创建与任务拆解体验优化"的产品机会主线。部分能力已经在 V0.8.x 静态原型中抢跑出现，但后续 PRD 和设计补齐不再继续扩展这些系统级能力。

| 非目标 | 理由 |
|---|---|
| 完整模板市场/模板商店 | 当前阶段只需要 4 个内置模板，模板市场属于 P2 后续迭代 |
| 多视图系统（日历、甘特、列表） | 已有静态演示资产，但偏产品增强，不属于新手创建核心 |
| 复杂自动化配置 | 属于进阶能力，不应进入新手创建向导 |
| 团队权限体系重构 | 属于系统级能力，不作为本次产品机会主线 |
| 登录注册和真实鉴权 | 静态原型项目，不涉及后端 |
| API、Webhook、插件系统 | 已有静态演示资产，但属于开发者/运维能力，与新手创建无关 |
| 数据库、后台任务、Docker 部署 | 属于实例级运维能力，V0.8.28 已暂停 |
| 真实文件上传和服务端存储 | 静态原型，不做真实文件传输 |
| 真多用户实时协作 | 静态原型，不做多人实时协作 |
| 邮件发送、RSS/iCalendar 订阅 | 已有静态表达时仅作为复现资产，不作为本次优化范围 |

## 11. 约束与风险

### 约束

| 约束 | 说明 |
|---|---|
| 静态原型定位 | 当前实现是静态 HTML/CSS/JS 原型，数据存储在浏览器 localStorage，不具备后端能力 |
| 学习实战项目 | 本项目定位为产品经理学习实战，不是真实产品上线，因此部分指标（如真实用户行为数据）无法在当前阶段获取 |
| 现有实现资产 | V0.3-V0.8.27 已有大量静态实现，后续设计决策需要考虑与现有实现的兼容性 |
| 桌面研究基础 | 用户假设和竞品分析基于桌面研究，尚未通过真实用户访谈验证 |

### 风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 用户假设未经验证 | 设计方案可能偏离真实用户需求 | PD-002 用户研究计划中安排可用性测试 |
| PRD 与实现倒挂 | 当前实现已远超 PRD 定义范围 | PRD 定义理想方案，评估实现差距，而非文档化现有实现 |
| 作品集时间有限 | P0-P2 补齐工作量可能超出预期 | 根据剩余时间决定 P0-P2 的深度和取舍 |
| 功能复现惯性 | 可能回到"继续堆功能"的工作模式 | 明确暂停 V0.8.28，主线切换为产品设计补齐 |

## 12. 后续需要验证的问题

1. **新手是否真的会卡住**：当前痛点基于桌面研究假设，需要通过可用性测试验证新手面对空白 Kanboard 时的真实行为。
2. **模板是否真的能降低创建成本**：需要通过可用性测试对比空白创建和模板创建的首次完成率、耗时和看板质量。
3. **示例卡的设计是否有效**：需要观察用户是否参考示例卡的写法，还是直接删除所有示例卡。
4. **4 个模板是否覆盖核心场景**：需要验证个人学习、求职准备、小团队迭代、Bug 跟踪这 4 个场景是否是目标用户的真实高频场景。
5. **字段微文案是否有帮助**：需要观察用户对负责人、优先级、截止时间的理解是否因微文案而改善。
