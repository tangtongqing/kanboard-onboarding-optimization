## 1. 执行摘要

Kanboard 的轻量、自托管和规则清晰构成了产品优势，但第一次使用看板的用户仍要自己完成三次判断：选择合适的列结构、把目标拆成可执行任务、理解泳道和 WIP 等概念。这使“创建项目”不等于“获得一张可用看板”。

市场机会不是把 Kanboard 改造成复杂的模板平台，而是在现有创建入口内增加一座低干扰的新手桥梁：让用户按场景选择模板、预览结果、生成可编辑示例任务，并在创建后完成第一次真实操作；熟练用户仍能直接创建空白项目。

## 2. 市场背景与机会

### 2.1 产品背景

- Kanboard 是开源、自托管、以 Kanban 方法为核心的轻量项目管理工具。
- 轻量产品减少了系统配置，但也把“如何搭建第一张看板”的方法成本留给了用户。
- Trello、Notion 等产品通过模板和示例内容降低冷启动成本，说明“把方法装进模板”是成熟的新手体验模式。
- 本项目以静态可交互原型验证方案可实现性，不代表已证明真实市场需求或商业结果。

### 2.2 机会陈述

**在 Kanboard 新建项目流程中提供“空白项目 / 从模板开始”双路径，让新手在 3 个主要步骤内获得一张可用看板，同时保持熟练用户的原有创建效率。**

### 2.3 市场问题

| 用户任务 | 当前摩擦 | 可能后果 | 产品机会 |
|---|---|---|---|
| 从目标建立项目 | 面对空白项目，不知道先建什么 | 放弃创建或随意搭建 | 场景模板与结构预览 |
| 把目标拆成任务 | 缺少任务粒度参考 | 卡片过大、过虚或不可执行 | 高质量可编辑示例卡 |
| 理解看板方法 | 不理解列流转、泳道、WIP | 把看板当普通清单 | 就地白话解释与首次操作引导 |
| 开始真实使用 | 创建后没有下一步 | 停留在“看到了但没行动” | 0/3 激活 Checklist |
| 快速建立空白项目 | 新手流程可能打扰熟练用户 | 降低效率与接受度 | 保留空白快捷路径、引导可退出 |

## 3. 市场细分

市场按“用户要完成的任务”划分，不按年龄或职业标签划分。

### 3.1 首要细分：需要把模糊项目变成执行计划的个人学习者

- 典型任务：课程学习、求职准备、作品集制作、个人项目。
- 现有替代方案：待办清单、Excel、Notion 页面、纸笔。
- 核心障碍：知道目标，但不知道列结构与任务粒度。
- 预期价值：快速获得可参考、可修改、可继续推进的项目骨架。
- 选择理由：使用场景清晰，单人决策链短，最适合先验证“模板是否降低冷启动成本”。

### 3.2 次要细分：希望低配置管理个人产品的开发者

- 典型任务：功能迭代、Bug 跟踪、发布准备。
- 现有替代方案：GitHub Issues、简单 TODO、Trello、手写 Markdown。
- 核心障碍：不愿为轻量项目配置复杂工作流。
- 预期价值：从 Bug 跟踪或小版本迭代模板直接开始，再按需修改。

### 3.3 扩展细分：需要统一轻量协作流程的小团队负责人

- 典型任务：2-5 人小团队的任务推进、评审与交付。
- 现有替代方案：群聊、共享表格、飞书/Notion、Trello。
- 核心障碍：团队成员对列状态、负责人、优先级和完成标准理解不一。
- 预期价值：用模板统一最小工作流，减少第一次配置和解释成本。

### 3.4 暂不优先的市场

- 需要复杂权限、审计、合规、跨部门资源管理的企业客户。
- 需要真实多人协同、服务端同步和生产级监控的团队。
- 希望获得大型模板市场、AI 自动拆解或全套项目组合管理的用户。

## 4. 核心 Job to Be Done

> 当我第一次用看板管理一个还比较模糊的目标时，我希望快速看到一个适合该场景的工作流和任务示例，并能把它改成自己的内容，这样我不用先学习项目管理方法，也能马上开始推进。

相关任务：

1. 判断空白创建还是模板创建更适合当前目标。
2. 在创建前知道系统将生成什么，避免试错。
3. 理解一张“可执行任务卡”应包含什么。
4. 通过编辑、拖动和新建卡片完成第一次真实行动。
5. 在需要时理解术语，但不被强制教程打断。

## 5. 竞品与替代方案

| 维度 | Kanboard 当前基础 | WeKan | Trello | Notion | 本项目要求 |
|---|---|---|---|---|---|
| 产品定位 | 轻量开源看板 | 开源协作看板 | 商业看板与协作 | 综合工作区 | 保持 Kanboard 轻量定位 |
| 新手起点 | 创建项目后自行搭建 | 创建/加入看板 | 可从模板开始 | 可从模板页面开始 | 双创建路径 |
| 模板与示例 | 需要较多自行配置 | 依看板配置 | 模板生态成熟 | 场景模板丰富 | 只做 4 个内置场景模板 |
| 方法教学 | 偏文档与工具规则 | 偏协作配置 | 在模板中隐性教学 | 在页面结构中隐性教学 | 在做中教 |
| 熟练用户效率 | 高 | 中 | 中 | 中 | 不增加空白创建步骤 |
| 自托管与可控性 | 强 | 强 | 弱 | 弱 | 保留本地、轻量、可控优势 |

### 5.1 差异化定位

**面向希望保持轻量和数据可控、又不熟悉看板搭建方法的个人与小团队，提供“场景模板 + 可编辑示例 + 一次性行动引导”的低干扰冷启动体验。**

差异不来自模板数量，而来自：

- 与现有创建入口融合，不建立复杂模板市场。
- 示例内容可修改、可删除、可放弃。
- 通过 Checklist 和局部提示促成第一次行动。
- 对空白项目和已完成引导的用户保持零打扰。

## 6. 市场需求

### 6.1 必须满足（P0）

| 市场需求 ID | 需求 | 用户价值 | 判断标准 |
|---|---|---|---|
| MR-01 | 同时提供空白项目和场景模板 | 新手有帮助，熟练用户不受阻 | 两条路径同屏可见 |
| MR-02 | 提供个人学习、求职准备、小团队迭代、Bug 跟踪 4 个模板 | 覆盖首批高频任务 | 模板名称与内容按任务场景组织 |
| MR-03 | 创建前预览列结构和示例任务 | 降低选择风险 | 用户确认结果后再创建 |
| MR-04 | 自动生成可编辑、可删除的示例卡 | 展示合理任务粒度 | 示例不是只读教程 |
| MR-05 | 创建后引导用户完成编辑、拖动、新建卡片 | 从“创建”走到“激活” | 3 个动作均可独立完成 |
| MR-06 | 关键术语提供就地白话解释 | 减少离开当前流程查资料 | 桌面与移动端均可触发 |
| MR-07 | 首次操作提示一次性、可关闭、会避让高层组件 | 控制干扰 | 完成或关闭后不重复 |
| MR-08 | 390px 视口保持主要任务可用 | 支持移动浏览与演示 | 无横向溢出和关键按钮遮挡 |

### 6.2 应该满足（P1）

- 根据真实研究结果调整模板覆盖与默认创建策略。
- 支持把现有项目保存为自定义模板。
- 接入真实事件平台，建立创建到首次行动的漏斗。
- 在真实设备上验证触控、弹层与键盘行为。

### 6.3 暂不满足（P2）

- 模板市场与第三方模板生态。
- AI 自动拆解与服务器推理。
- 企业级权限、审计和多人实时协同。
- 生产级支付、账号、后端存储和跨设备同步。

## 7. 价值主张

### 7.1 对新手

- 不从空白页开始，而是从可理解的场景开始。
- 不先读教程，而是在修改和拖动中理解看板。
- 不被模板锁定，所有示例都能变成自己的内容。

### 7.2 对熟练用户

- 空白创建仍是直接路径。
- 引导按项目保存状态，完成或关闭后不再出现。
- 帮助信息按需触发，不占用主工作区。

### 7.3 对产品

- 用较小范围改善首次成功体验，不改变核心定位。
- 能定义从创建、激活到首次操作的可测量漏斗。
- 形成可逐步验证的产品假设，而不是继续堆叠系统能力。

## 8. 成功指标与验证门槛

当前原型没有真实流量或服务端埋点，以下是上线试验目标，不是已经取得的结果。

### 8.1 北极星指标

**首次可用看板激活率**：首次创建项目的用户中，在限定时间内完成至少一次真实任务编辑、拖动或新增的比例。

### 8.2 关键指标

| 指标 | 定义 | 期望方向 |
|---|---|---|
| 首次项目创建完成率 | 创建成功人数 / 打开创建入口人数 | 提升 |
| 首次创建耗时 | 打开入口到进入可用看板的时长 | 下降 |
| 3 分钟首次行动率 | 创建后 3 分钟内完成真实操作的比例 | 提升 |
| 模板选择率 | 选择模板创建的项目 / 全部新项目 | 观察，不预设越高越好 |
| 示例卡转化率 | 被编辑为真实任务的示例卡 / 被查看示例卡 | 提升 |
| Checklist 完成率 | 完成 3/3 的模板项目 / 展示 Checklist 的项目 | 提升 |
| 空白路径耗时 | 熟练用户完成空白创建的时长 | 不劣化 |

### 8.3 首轮研究门槛

- 招募 5-8 名目标用户完成空白路径与模板路径对照测试。
- “可用看板”至少包含 3 个合理状态列、3 张可执行任务，且用户能说明下一步如何推进。
- 记录完成率、耗时、卡住点、示例卡修改行为与主观帮助度。
- 样本只能用于发现明显问题和趋势，不用于统计显著性结论。

## 9. 推广与采用路径

本项目当前是公开静态演示，不是商业产品发布。建议的采用路径为：

1. 通过设计案例页和产品体验页让目标用户理解方案并直接试用。
2. 首轮以学生、产品学习者和个人开发者为研究对象，验证冷启动问题。
3. 根据研究结果调整模板、默认路径和引导强度。
4. 只有当模板路径明显改善首次成功且不损害空白路径时，才考虑进入真实 Kanboard 插件或生产功能开发。

## 10. 风险与约束

| 风险/约束 | 当前情况 | 应对 |
|---|---|---|
| 缺少真人研究 | 用户问题主要来自桌面研究与公开案例 | 明确假设标签，执行研究计划 |
| 缺少市场规模数据 | 未建立 TAM/SAM/SOM | 不做规模和收入承诺 |
| 静态原型限制 | localStorage、无后端、无账号 | 只验证交互可达性 |
| 模板覆盖可能偏差 | 4 个模板由项目判断产生 | 用访谈和选择行为校准 |
| 引导可能过度 | Checklist、Tooltip、Popover 可能叠加 | 可退出、一次性、互斥避让 |
| 移动验证有限 | 仅 Chromium 390px 视口 | 后续补真实 iOS/Android |
| 商业价值未验证 | 无付费、转化或留存数据 | 不将静态演示结果包装成业务成果 |

## 11. 证据与假设登记

| 结论 | 证据级别 | 状态 |
|---|---|---|
| Kanboard、WeKan、Trello、Notion 的功能与创建方式存在差异 | 桌面研究 | 已记录 |
| 模板和示例内容是成熟产品常用的冷启动方式 | 竞品研究 | 已记录 |
| 本项目的交互路径与状态可以在静态原型中运行 | 自动化与浏览器验证 | 已验证 |
| 新手普遍会在空白看板中卡住 | 用户假设 | 待验证 |
| 模板会提升完成率、缩短耗时 | 产品假设 | 待验证 |
| 4 个模板覆盖首批目标用户的高频任务 | 市场假设 | 待验证 |
| Checklist 与首次操作提示会提升激活率 | 方案假设 | 待验证 |
