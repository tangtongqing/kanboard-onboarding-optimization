## 1. 基础设计系统规范延续 (Clarity 风格)

所有的轻引导组件设计必须严格延续 `docs/03-ux-design/设计系统整理-PD-009.md` 以及 `docs/03-ux-design/高保真视觉规格-PD-011B.md` 中确立的 Clarity 工具型 SaaS 原则：

*   **局部气泡 (Popover)**：
    *   **背景色**：`#313131` (深灰，避免采用营销风彩色，确保工具专业感)。
    *   **前景色/文字**：`#FFFFFF` (纯白)，高对比度。
    *   **文字字号**：`12px` (Regular, line-height: 16px)。
    *   **圆角**：`4px` (小圆角以匹配现有卡片与输入框)。
    *   **投影 (Box Shadow)**：`0 2px 6px rgba(0, 0, 0, 0.20)`。
    *   **边缘关闭按钮**：`10px` 交叉号，颜色 `#A6A6A6`，Hover 时变为 `#FFFFFF`。
    *   **小三角形指针 (Arrow)**：高度 `6px`，宽度 `12px`，基准色 `#313131`，根据定位方向（上/下/左/右）动态翻转。
*   **首次删除拦截弹层 (Overlay Dialog)**：
    *   **背景色**：`#FFFFFF` (纯白)。
    *   **遮罩色 (Backdrop)**：`rgba(0, 0, 0, 0.40)`。
    *   **动作按钮**：
        *   “取消删除”（主操作）：蓝色文字，底色 `#EBF3FC`，Hover 时底色 `#D9E8FA`，高度 `36px`，字重 `Semibold`。
        *   “确认删除”（高危次操作）：红色文字，底色 `#FDE8E8`，Hover 时底色 `#FBD0D0`，高度 `36px`。
*   **移动端轻引导条 (Tap Inline Strip)**：
    *   **高度**：`32px`，底色 `#EBF3FC`，文字底色 `#1D52B7`，无 Hover 态，使用 Tap 关闭。

## 3. 各 Frame 视觉布局与标注细节 (Specs Breakdown)

### Frame 01: `Desktop - 1st Drag Popover`
*   **挂载锚点**：首张卡片（`待学` 列的第一个卡片 `#card-1`）。
*   **绝对定位**：气泡底边缘距离卡片顶边缘 `8px`。
*   **Popover 规格**：
    *   尺寸：`240px` 宽度，`48px` 高度。
    *   文字：`你可以把卡片向右拖动，推进任务状态。` 换行对齐，左侧带微型拖拽小图标，右侧带极细关闭叉号（距离右边界 8px，上边界 8px）。
    *   指示针：正下方中轴位置，三角形朝下。

### Frame 02: `Desktop - 1st Edit Dot & Popover`
*   **呼吸红点 (Status Dot)**：
    *   颜色：`#E65100` (橙红) 伴随 `rgba(230, 81, 0, 0.2)` 外发光。
    *   位置：卡片标题文本尾部。
*   **Popover 规格**：
    *   方向：朝上，指示针居中指向红点位置。
    *   文案：`双击可把示例卡改成你的真实任务。`

### Frame 03: `Desktop - 1st Delete Modal`
*   **弹窗规格**：
    *   尺寸：`360px` 宽度，`160px` 高度，水平垂直居中。
    *   结构：
        *   顶部标题（`14px Semibold`）: `彻底删除任务吗？`
        *   中部解释（`12px Regular`，颜色 `#666`）: `删除会彻底移除此卡片，本地数据不可恢复。这是你第一次删除操作，确认要继续吗？`
        *   底部按钮区：右对齐，间距 `12px`。“取消删除”（高亮浅蓝底），“确认删除”（粉红底红字）。

### Frame 04: `Desktop - Task Menu Guidance`
*   **挂载锚点**：当点击 `⋯` 按钮展示的弹出式菜单（Dropdown Menu）出现时。
*   **绝对定位**：气泡居于 Dropdown 面板右侧，距离面板 `6px`，指示针水平朝左指向菜单上的“克隆/移动”项。
*   **文案**：`这里还有复制、关闭、移动等更多操作。`

### Frame 05 & 06: `Desktop - Suppressed States`
*   **互斥抑制逻辑视觉表现**：
    *   **Frame 05** 中，当全局 Checklist Panel (`#onboardingPanel`) 展开占居屏幕右侧时，即使光标悬停卡片，气泡不弹出。设计图中使用橙色虚线标注框 `[Suppressed: Checklist Open]` 表示判定抑制。
    *   **Frame 06** 中，当 WIP 限制的问号 Tooltip 气泡激活在看板顶列时，原有的卡片轻引导气泡透明度调整为 `0%`（即不渲染）。

### Frame 09: `Mobile 390px - Inline Tap Popover`
*   **挂载形式**：不使用 Hover。直接作为 Inline 元件嵌在卡片组件标题下方、元数据标签上方。
*   **样式**：
    *   高度自适应，底色 `#F6F8FA`，左侧带有 `1.5px` 的浅蓝色装饰线条。
    *   文本：`点击卡片右下角 ⋯ 菜单或双击修改任务` (字号 `11px`)。
    *   触控关闭：最右侧带关闭按钮，触控靶区大小 `24px * 24px`。

### Frame 10: `Mobile 390px - Delete Bottom Sheet`
*   **挂载形式**：在窄屏下放弃 Modal 弹窗，改用符合移动端单手交互的 Bottom Sheet。
*   **样式**：
    *   从屏幕底部向上滑出占屏高度 `30%` 的浅色 Drawer。
    *   “确认删除” 与 “取消删除” 两个按钮垂直堆叠，按钮高度为 `44px`，符合触控易用性（Clarity 移动端规范），防止误触。

## 4. 空间与事件层级关系 (Layering & Z-index Specification)

在后续前端实现中，所有浮动图层的 `z-index` 必须严格遵循以下高保真设计规范，防止发生穿透遮挡问题：

```text
+----------------------------------------------+
| [层级 5] 主弹窗 / 侧滑抽屉 (Dialog / Drawer)     |  z-index: 100
+----------------------------------------------+
| [层级 4] 轻反馈气泡 (Toast Notifications)     |  z-index: 95
+----------------------------------------------+
| [层级 3] 字段术语解释帮助层 (Tooltip)          |  z-index: 92
+----------------------------------------------+
| [层级 2] 首次核心操作轻引导 (Guidance Popover) |  z-index: 90
+----------------------------------------------+
| [层级 1] 基础操作看板与卡片 (Kanboard / Card)   |  z-index: 1~10
+----------------------------------------------+
```

*   **互斥事件链**：当 `z-index: 100` 的组件激活时，系统处于 **Modal 模态状态**，此时所有低于其层级（`z-index: 90`）的轻引导气泡会被**事件捕获器完全冻结或销毁**，避免用户在交互 Dialog 时受到背景气泡的干扰。

## 5. 后续 PD-019C 前端实现注意事项

1.  **localStorage 防呆设计**：
    *   在加载页面时检查当前项目的类型。只有当项目符合“场景模板”或“非空（创建了首张卡片）的空白项目”条件时，才初始化状态为 `not_seen`。
    *   严防因重复初始化将已标记为 `dismissed` / `completed` 的数据写回，防止对老用户造成二次打扰。

    *   代码实现时要监听 `touchstart` / `touchend` 事件，或直接采用 Frame 09 的 Inline 标签设计，代替 `mouseenter` / `mouseleave` 桌面特有事件。
3.  **测试绿灯守卫**：
    *   在后续开发代码时，必须保证现有的 408 项静态功能断言依旧保持全绿通过，不能破坏已稳定的 Baseline。
