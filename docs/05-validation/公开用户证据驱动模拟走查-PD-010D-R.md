> **版本性质：公开二手研究 + 证据驱动模拟 / 非真人可用性测试 / 不计入 P01~P08**

| 项目 | 内容 |
|---|---|
| 日期 | 2026-06-22 |
| 产品 | Kanboard 新手项目创建与任务拆解优化 |
| 目标用户 | 初次或低频创建项目的个人用户、小团队成员与管理员 |
| 研究范围 | 项目模板、创建默认路径、模板信息层级、未保存保护、移动端创建与触摸体验 |
| 时间范围 | 2017~2026；优先使用 2021~2026 证据，早期模板证据只作长期行为信号 |

## 1. 执行摘要

公开证据支持本项目的问题方向，但不能替代对 T01~T10 的真实测试。Kanboard 的正式创建流程强调“只需项目名”，同时允许从已有项目复制权限、动作、泳道、分类和任务；这解释了为什么一部分用户把已有项目当成模板，并高度在意复制完整性。[Kanboard 官方 Projects 文档](https://docs.kanboard.org/v1/user/projects/)

团队型用户表现出“标准项目重复创建”的稳定行为：有人长期依赖复制模板项目，有人每次新建后立即补权限，也有人因任务顺序、日期、权限或外链没有完整复制而遇到问题。这类用户会在创建前检查模板结构和复制范围，而不是只看模板名称。[GitHub #3434](https://github.com/kanboard/kanboard/issues/3434) [GitHub #4909](https://github.com/kanboard/kanboard/issues/4909) [GitHub #4153](https://github.com/kanboard/kanboard/issues/4153) [GitHub #2329](https://github.com/kanboard/kanboard/issues/2329)

个人用户的另一条信号是“够用、快速、少负担”。公开评论把 Kanboard 描述为适合小型或个人项目、速度快，但也有人认为它偏组织化、界面不够直观或卡片元数据过重。[HN 36055423](https://news.ycombinator.com/item?id=36055423) [HN 39745588](https://news.ycombinator.com/item?id=39745588) [HN 37072837](https://news.ycombinator.com/item?id=37072837) [GitHub #5746](https://github.com/kanboard/kanboard/issues/5746)

移动端问题是最强的当前风险信号：公开 issue 覆盖无法横向滚动、小触摸拖拽目标导致误触、iPad 新建项目失败和弹窗未充分利用视口；公开评论也记录了因移动体验较差而转向其他产品的行为。[GitHub #5736](https://github.com/kanboard/kanboard/issues/5736) [GitHub #4302](https://github.com/kanboard/kanboard/issues/4302) [GitHub #4727](https://github.com/kanboard/kanboard/issues/4727) [GitHub #5382](https://github.com/kanboard/kanboard/issues/5382) [HN 36055189](https://news.ycombinator.com/item?id=36055189)

未保存保护也有直接外部证据：用户报告按 ESC 意外退出并丢失大量编辑，长期用户则强调弹窗关闭行为一致性和 dirty-form 保护的重要性。这支持 PD-010B 的 R14 修复，但不是对当前具体确认文案的验证。[GitHub #5505](https://github.com/kanboard/kanboard/issues/5505) [GitHub #5395](https://github.com/kanboard/kanboard/issues/5395)

## 2. 证据标签与限制

| 标签 | 含义 | 可用于 |
|---|---|---|
| `[公开事实]` | 来源中明确描述的行为、问题或正式功能 | 支撑问题存在、用户目标和上下文 |
| `[跨源模式]` | 多个独立公开来源指向同一方向 | 提高问题方向的可信度 |
| `[推断]` | 从公开行为映射到本项目结构选择 | 生成待验证假设，不得写成用户结论 |
| `[模拟]` | 基于证据画像对 T01~T10 的预测行为 | 专家走查输入，不计真实样本 |

限制：

- GitHub issue 和社区评论是自选择样本，不能推断问题发生比例。
- 早期模板 issue 能说明长期需求，但不能代表 2026 年当前界面的频率。
- 公开来源没有参与者直接操作 T01~T10，因此无法产生完成率、耗时、偏好票数或统计显著性。
- Hacker News 同一作者的多条评论只算一个观点来源，避免伪造“多人一致”。
- 搜索接口曾返回 403；本轮通过 GitHub CLI、GitHub API、Hacker News Algolia API 和官方文档源直接检索。Reddit 信号未稳定取得，属于来源缺口。

## 3. 公开证据簇

### 3.1 重复创建与模板完整性

| 公开证据 | 观察 | 对本项目的意义 |
|---|---|---|
| 官方文档 | 新项目可从已有项目复制权限、动作、泳道、分类和任务 | 用户需要理解“会复制什么”，模板预览不能只表达名称 |
| GitHub #3434 | 团队依赖多个模板项目反复复制，且在模板中持续补任务 | 重复创建用户会把模板当作长期维护的结构资产 |
| GitHub #4909 | 小团队每次新建后立即编辑权限并加入全部成员/组 | 创建完成并非流程终点，默认权限是后续固定动作 |
| GitHub #4153 / #2329 | 复制后的日期或权限未满足预期 | 用户会用“是否完整继承”判断模板可信度 |

**跨源模式**：团队用户不是随机挑一个看起来合适的模板，而是在判断模板能否稳定复用已有工作方式。

### 3.2 个人用户的轻量偏好

| 公开证据 | 观察 | 对本项目的意义 |
|---|---|---|
| HN 36055423 | 长期用于小型个人项目 | 个人用户不一定需要团队权限和复杂预设 |
| HN 39745588 | 强调速度、轻量与小项目适配 | 创建流程不应因为模板能力牺牲快速空白路径 |
| HN 37072837 | 个人看板用户认为产品仍偏组织化 | 元数据过多可能制造“这是给团队的”感受 |
| GitHub #5746 | 单人用户认为未分配标签占据卡片空间 | 信息密度是实际摩擦，不是单纯审美偏好 |

**跨源模式**：个人用户更可能先追求快速建立一个可用容器，再逐步添加结构。

### 3.3 移动端可达性与误触

| 公开证据 | 观察 | 对本项目的意义 |
|---|---|---|
| GitHub #5736 | Android 上公开看板无法横向滚动，部分列不可见 | 移动端必须验证真实滚动与裁切，线框无法代替真机 |
| GitHub #4302 | 拖拽目标太小，用户经常误开任务 | 44px 触摸目标和操作间距具有真实行为依据 |
| GitHub #4727 | iPad Safari 点击新建项目后重载或崩溃 | 新建流程需要真机/浏览器组合验证 |
| GitHub #5382 | 弹窗没有利用可用高度，长文本编辑受限 | 全屏/边距选择的核心是有效空间和操作可达性 |
| HN 36055189 | 用户因移动体验较差转向更移动友好的产品 | 移动问题可能导致替换行为，不只是轻微不满 |

**跨源模式**：V06 的优先级高，但公开证据只能确认“移动创建必须可滚动、可触达、少误触”，不能直接裁决全屏或 16px 边距。

### 3.4 未保存内容与弹窗一致性

| 公开证据 | 观察 | 对本项目的意义 |
|---|---|---|
| GitHub #5505 | ESC 意外退出导致用户丢失大量编辑 | dirty 状态关闭确认是数据保护，不是装饰性提示 |
| GitHub #5395 | 长期用户在意背景点击关闭、dirty form 和行为一致性 | 关闭机制需要可预期，不能每个弹窗各自处理 |

**跨源模式**：R14 的问题方向有真实用户证据支持；确认文案、焦点恢复和是否使用原生 confirm 仍需本项目验证。

### 3.5 简单可靠与界面理解成本并存

| 公开证据 | 观察 | 对本项目的意义 |
|---|---|---|
| HN 36057173 | 机构用户认为产品可靠但不直观，导致部分人回避使用 | 结构清晰度会影响采用，而不只是任务效率 |
| HN 44158149 | 用户概括为“外观粗糙但有用” | 视觉升级应保留功能直接性，不能只做装饰 |
| HN 44158914 | 用户认为 UI/UX 不足 | V04 信息层级和 PD-011 视觉探索有外部方向性依据 |
| HN 40062808 | 另一长期用户称其简单、快速 | 改进不能破坏 Kanboard 的轻量优势 |

## 4. 证据驱动模拟画像

以下 S01~S04 不是参与者，不计入样本数，也不生成引语、评分或时间。

### S01 标准流程复用者

**证据基础**：官方复制能力、#3434、#4909、#4153、#2329。

**模拟行为**：

1. 打开模板列表后先寻找是否接近现有团队流程。
2. 在 T01 精简卡片上会继续进入预览，因为只知道数量，无法判断列名和任务是否符合标准流程。
3. 在 T02 扩展卡片上能更早排除不匹配模板，但仍会核对权限、动作和复制范围。
4. 在 T03/T04 中更可能使用 T04 分区逐项检查列、泳道和示例任务。
5. 创建后立即进入权限与成员配置，而不是停留在成功页。

**推断置信度**：中。重复创建行为有直接证据，但没有人操作过本项目 T01~T04。

### S02 个人轻量用户

**证据基础**：HN 36055423、39745588、37072837，GitHub #5746。

**模拟行为**：

1. 先扫描是否存在“空白项目”或最简单模板。
2. T02 的长列名链和示例任务可能被视为额外阅读负担。
3. 更可能接受 T01 精简卡片，只有在不确定时才打开预览。
4. 对 V05b 默认空白更少意外，但这只是画像推断；公开证据没有验证名称位置。
5. 创建后倾向删掉不相关示例卡或直接从空白开始。

**推断置信度**：中低。轻量偏好有多源证据，V05 默认选择没有直接证据。

### S03 移动快速记录者

**证据基础**：#5736、#4302、#4727、#5382、HN 36055189。

**模拟行为**：

1. 首先测试页面能否滚动、底部操作是否持续可见，而不是比较视觉风格。
2. 若点击目标小或操作靠近拖拽区，可能误触模板卡或任务。
3. T07 全屏提供更多有效宽度，可能减少拥挤；T08 保留上下文但必须确保 sticky 区不遮挡内容。
4. 只看纸面状态无法判断哪种容器真机更好，因此不会在 V06a/V06b 之间给出确定结论。

**推断置信度**：移动风险中高；容器偏好低。

### S04 编辑保护敏感用户

**证据基础**：#5505、#5395。

**模拟行为**：

1. 输入名称或描述后，会把 ESC、右上角关闭和背景点击视为潜在退出路径。
2. 若关闭无确认，风险是内容丢失；若所有关闭都强制确认，pristine 状态会显得拖沓。
3. 期望 dirty 状态明确保护、继续编辑后内容保留，且不同弹窗行为一致。

**推断置信度**：高于其他模拟项，因为存在直接的内容丢失行为报告。

## 5. V03~V06 方向性判断

| 变体 | 公开证据支持 | 公开证据不支持 | 模拟走查建议 | 置信度 |
|---|---|---|---|---|
| V03 信息密度 | 团队复用者需要结构细节；个人用户反感冗余 | 没有直接 A/B 偏好 | 保留 V03a 为默认，复杂模板提供渐进展开或快速进入详细预览 | 中 |
| V04 预览层级 | 复制完整性和界面不直观问题支持清晰分区 | 没有直接复述测试 | 暂保留 V04b；简单模板降低视觉重量，但不删除语义分区 | 中低 |
| V05 默认方式/名称位置 | 团队用户偏复用，个人用户偏轻量 | 没有公开来源验证默认项或名称位置 | 维持当前 V05a 仅作项目目标下的暂定方案；保持空白路径一键可见 | 低 |
| V06 移动容器 | 滚动、触摸目标、视口利用和新建失败均有证据 | 没有全屏 vs 16px 的直接比较 | 不裁决 V06a/V06b；先守住 sticky、44px 触摸目标、无裁切和真机兼容 | 风险中高，方案选择低 |

## 6. 对现有整改的外部校准

| 项目问题 | 外部证据 | 校准结论 |
|---|---|---|
| R08 移动端底部操作 | 移动滚动、视口和触摸问题多源存在 | 继续视为核心移动门槛，仍需真机 |
| R11 示例卡身份 | 复制用户在意“哪些内容会被带入” | 支持解释复制内容，但“示例”徽标本身无直接外部验证 |
| R14 未保存关闭 | ESC 丢失编辑和 dirty-form 讨论 | 修复方向得到直接支持 |
| R06 名称错误反馈 | 官方文档称创建只需名称 | 名称是最小关键输入，错误必须明确；行内 ARIA 细节仍属本项目规范 |

## 7. Gate 结论

公开证据驱动模拟走查可以：

- 证明问题方向不是纯 AI 想象；
- 给 V03~V06 提供更可信的待验证假设；
- 支持 R08/R14 的优先级；
- 允许 PD-011 在 `Conditional Go` 下做不定稿的有限视觉探索。

它不能：

- 计作 P01~P08 真人样本；
- 填写完成率、耗时、偏好票数或参与者原话；
- 声称 T01~T10 已验证；
- 把 Gate 升级为完整 Go。

**当前 Gate 保持 `Conditional Go`。** 若项目选择暂不招募真人，可以继续 PD-011 的探索稿，但必须在作品集和文档中标注“公开二手研究 + 证据驱动模拟，未完成一手可用性测试”。
