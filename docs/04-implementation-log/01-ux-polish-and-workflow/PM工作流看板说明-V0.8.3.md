# PM 工作流看板说明 V0.8.3

| 项目 | 内容 |
|---|---|
| 日期 | 2026-06-02 |
| 主题 | 用 Kanboard 复现完整产品开发流程 |
| 目标 | 让默认示例不只是功能演示，而是能表达 PM 从提需到上线维护的完整工作链路 |
| 范围 | 默认演示项目数据、顶部指标口径、验收脚本、设计截图 |

## 为什么要补这一版

上一版页面已经完成 Kanboard 静态功能和视觉重设计，但默认任务内容仍偏“复现项目本身”。这会导致用户打开页面后，只能看出它是一个看板工具，却不容易学到产品经理如何用看板管理真实项目。

这一版把默认项目改为“产品开发全流程项目”，让页面内容直接服务于产品经理学习：

- 需求从哪里来。
- PM 如何澄清需求。
- PRD 和原型如何进入评审。
- 如何对接研发、测试、运营。
- 上线后如何看反馈、做复盘、进入下一轮迭代。

## 看板列结构

| 列 | 含义 |
|---|---|
| 需求池 | 收集业务方提需、用户反馈、竞品机会点 |
| 需求澄清 | 明确问题、目标用户、成功指标和优先级 |
| 产品方案 | 输出 PRD、原型、埋点和 MVP 范围 |
| 评审排期 | 产品评审、技术评审、排期和验收标准 |
| 研发实现 | 开发进度、接口联调、需求变更管理 |
| 测试验收 | 测试用例、缺陷修复、PM 走查 |
| 上线运营 | 灰度发布、上线公告、运营话术和监控 |
| 反馈维护 | 上线反馈、数据复盘、下一轮迭代 |

## 泳道结构

| 泳道 | 用途 |
|---|---|
| 需求与用户泳道 | 放提需、用户反馈、访谈、竞品和问题定义任务 |
| 产品方案泳道 | 放 PRD、原型、评审材料、验收标准和埋点任务 |
| 研发测试泳道 | 放技术评审、开发、联调、测试和发布保障任务 |
| 运营反馈泳道 | 放运营素材、公告话术、上线反馈、复盘和维护任务 |

## 新增任务卡片

本轮默认项目从 3 张示例卡扩展到 24 张 PM 工作流卡片。每张卡片都尽量包含：

- 明确标题：表达 PM 具体动作。
- 描述：说明为什么做这件事。
- 负责人：PM、设计、研发、测试、运营、数据、客服等。
- 分类和标签：帮助演示筛选能力。
- 预估工时：用于项目分析和时间管理。
- 子任务：拆解执行步骤。

## 关键产品判断

- 列表示流程阶段，泳道表示协作工作流。这样比单纯“待办/进行中/已完成”更适合表达完整产品开发流程。
- 不把所有卡片都放在一个泳道里，避免看板只是横向流程图；通过泳道能看到 PM 如何跨角色协作。
- “反馈维护”不是结束，而是把上线结果重新转回需求池，所以卡片里保留“规划下一轮迭代需求”。
- 顶部“进行中”指标改为统计需求澄清、产品方案、评审排期、研发实现、测试验收、上线运营等活跃阶段。
