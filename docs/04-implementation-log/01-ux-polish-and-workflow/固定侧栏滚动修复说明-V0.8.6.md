# 固定侧栏滚动修复说明 V0.8.6

| 项目 | 内容 |
|---|---|
| 日期 | 2026-06-02 |
| 状态 | 已完成 |
| 主题 | 修复桌面端整页滚动问题，保证左侧导航固定、右侧工作区独立滚动 |
| 主要文件 | `styles.css`、`index.html`、`tests/static-feature-audit-v08.js`、`设计图/kanboard-v0.8.6-fixed-sidebar-scroll.png` |

## 问题

原布局中 `.app-shell` 只是普通页面网格，`.sidebar` 没有固定高度，`.workspace` 也没有独立滚动边界。看板内容变长后，浏览器整页滚动，左侧项目导航会跟着页面一起移动，用户切换项目时需要回到顶部。

## 修复方案

- 将桌面端页面锁定在 `100vh` 应用框架内。
- 左侧 `.sidebar` 设置为固定视口高度，并保持在左侧不随右侧内容滚动。
- 右侧 `.workspace` 设置为独立纵向滚动容器。
- `.board-shell` 不再被 flex 布局压缩成很矮的盒子，而是按看板内容高度参与右侧滚动。
- 移动端保留自然页面滚动，避免窄屏下侧栏和内容区被锁死。

## 验证结果

- `node --check app.js` 通过。
- `node --check tests/static-feature-audit-v08.js` 通过。
- `node tests/static-feature-audit-v08.js` 通过，共 87 项检查。
- 新增 3 项桌面布局断言：
  - 桌面端浏览器整页滚动被锁定在 app shell。
  - 右侧 `.workspace` 拥有纵向滚动。
  - 滚动右侧内容时左侧 `.sidebar` 保持固定。

## 产品判断

这次修复更接近 Kanboard 和常见后台工具的交互习惯：项目导航属于全局上下文，应该稳定停留；看板、筛选、泳道和任务卡属于工作区内容，应该在右侧独立滚动。
