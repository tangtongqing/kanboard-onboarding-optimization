# 全局用户与用户组管理补齐说明 V0.8.18

## 本轮目标

本轮继续根据 Kanboard 官网补齐系统级能力，将此前只有“项目内成员与用户组权限”的静态复现，扩展为“全局用户管理 + 全局用户组 + 项目授权引用”的结构。

## 官网依据

- Kanboard 用户文档说明：用户分为本地用户和远程用户；远程用户的凭据由 LDAP、反向代理或 OAuth2 等外部系统管理。
- 应用级角色包括 Administrator、Manager、User；项目级角色包括 Project Manager、Project Member、Project Viewer。
- 用户组类似团队或组织，只有管理员可以创建组和分配用户；项目经理可以在项目权限页授权用户组访问项目。
- 创建本地用户时用户名唯一，密码至少 6 位；远程用户只要求用户名。
- 删除用户后，分配给该用户的任务会变为未分配。
- 用户启用两步验证后，从 Kanboard v1.2.8 起 API 访问需要使用 API Key。
- User API 覆盖创建用户、创建 LDAP 用户、更新用户、删除用户、启用/停用用户等过程；Group API 和 Group Member API 覆盖创建组、更新组、删除组、添加/移除组成员等过程。

参考链接：
- https://docs.kanboard.org/v1/user/users/
- https://docs.kanboard.org/v1/api/user_procedures/
- https://docs.kanboard.org/v1/api/group_procedures/
- https://docs.kanboard.org/v1/api/group_member_procedures/

## 本轮新增

- 顶部新增 `用户管理` 入口。
- 新增全局身份目录 `state.identity.users`，和项目级 `project.settings.members` 分离。
- 新增全局用户组 `state.identity.groups`，支持组成员关系。
- 默认生成管理员、PM、设计、研发、测试、运营等用户。
- 默认生成产品研发测试小组、运营观察组两个用户组。
- 支持新增本地用户，校验本地用户密码至少 6 位。
- 支持新增远程用户，将密码/外部 ID 字段作为外部身份来源记录。
- 支持更新应用角色：管理员、经理、用户。
- 支持启用/停用用户。
- 支持开启/关闭 2FA，并显示 API Key 要求提示。
- 支持新增用户组、加入组、移出组、删除组。
- 删除用户时同步从用户组移除，并将该用户负责的任务改为未分配。
- 阻止停用、删除或降级最后一个启用状态的管理员。
- 任务负责人筛选与输入候选项纳入启用状态的全局用户。
- 将 localStorage key 升级为 `kanboard-static-v0818`，将项目 JSON 导出版本同步为 `kanboard-static-v0818`。

## 产品判断

Kanboard 的用户与组不是单个项目的附属信息，而是实例级身份基础设施。项目设置里的成员权限只能解决“这个项目谁能做什么”，但不能表达“系统中有哪些用户、哪些用户来自外部认证、哪些组可以被项目授权”。

因此本轮把权限模型拆成三层：

1. 全局用户：表示 Kanboard 实例里的账号和应用级角色。
2. 全局用户组：表示团队、组织或外部组同步结果。
3. 项目权限：在具体项目中引用用户或组，并赋予项目级角色。

这个结构更接近真实产品中的后台管理逻辑，也能帮助你理解产品经理在设计后台权限时为什么要区分“身份、组织、授权”。

## 静态复现边界

- 不做真实登录。
- 不做真实密码保存。
- 不连接 LDAP、反向代理或 OAuth2。
- 不生成真实 TOTP 二维码。
- 不生成真实 API Key。
- 不做后端权限拦截。
- 只在静态页面中模拟用户目录、角色、状态、2FA、用户组和组成员关系。
