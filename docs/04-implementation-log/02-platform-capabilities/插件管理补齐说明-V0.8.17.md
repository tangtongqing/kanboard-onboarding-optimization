# 插件管理补齐说明 V0.8.17

## 本轮目标

本轮继续按照 Kanboard 官网文档检查系统级功能缺口，补齐“插件管理”在静态复现中的表达。重点不是实现真实插件运行环境，而是让页面能完整表达管理员在 Kanboard 中看到的插件安装、更新、卸载与安全前置条件。

## 官网依据

- Kanboard 插件安装文档说明：从 Kanboard v1.2.8 起，Web UI 插件安装默认关闭；要从用户界面安装、更新、删除插件，需要插件目录可写、PHP Zip 扩展可用，并设置 `PLUGIN_INSTALLER=true`。
- 同一文档还说明：只有管理员可以从用户界面安装插件；默认只展示 Kanboard 网站上的插件，也可以通过 `PLUGIN_API_URL` 修改插件目录地址；插件提交没有代码审查流程，实例所有者需要自行验证插件是否合法。
- Kanboard CLI 文档提供了 `plugin:install`、`plugin:uninstall`、`plugin:upgrade` 等命令，说明插件管理不仅是页面入口，也属于管理员/运维侧能力。
- Kanboard 插件注册文档说明：插件存放在 `plugins` 目录中，Kanboard 会扫描插件目录并加载插件的 `Plugin.php`。

参考链接：
- https://docs.kanboard.org/v1/admin/plugins/
- https://docs.kanboard.org/v1/admin/cli/
- https://docs.kanboard.org/v1/plugins/registration/

## 本轮新增

- 顶部新增 `插件` 入口，打开插件管理弹窗。
- 新增插件安装器状态卡：展示安装器是否可用、已安装插件数、可安装插件数、可更新插件数。
- 新增安装器配置区：模拟 `PLUGIN_INSTALLER`、插件目录可写、PHP Zip 扩展可用和插件目录 URL。
- 默认关闭 Web UI 安装器，安装按钮不可用，符合 Kanboard v1.2.8 之后的安全默认值。
- 当安装器、目录权限、Zip 扩展都满足时，允许执行静态安装。
- 新增已安装插件列表，支持升级和卸载。
- 新增插件目录列表，支持安装未安装插件。
- 插件状态保存到 `localStorage`，刷新页面后仍可恢复当前静态数据。
- 将项目 JSON 导出版本同步为 `kanboard-static-v0817`，保持版本恢复链路一致。

## 产品判断

插件能力对 Kanboard 来说不是普通“设置项”，而是会影响系统行为和安全边界的管理员能力。因此静态复现时不能只放一个“安装插件”按钮，而要同时表达前置条件、默认关闭、安全提示和责任边界。

在产品设计上，本轮把插件管理拆成三个层次：

1. 状态总览：先告诉管理员当前能不能安装、有没有更新。
2. 安全前置：明确哪些条件阻止安装，不让用户误以为按钮坏了。
3. 操作列表：在条件满足后，才允许安装、更新、卸载。

这样的结构比单纯做一个插件表格更接近真实后台产品的决策顺序。

## 静态复现边界

- 不下载真实 Zip 包。
- 不写入真实 `plugins` 目录。
- 不执行 PHP 插件代码。
- 不做真实管理员权限鉴权。
- 不访问真实插件目录 API。
- 只在静态页面中模拟插件状态、安装条件和操作结果。
