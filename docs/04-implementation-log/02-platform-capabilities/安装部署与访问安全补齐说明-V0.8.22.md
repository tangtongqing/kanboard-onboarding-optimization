# 安装部署与访问安全补齐说明 V0.8.22

## 本轮目标
继续对照 Kanboard 官网管理端和部署文档，把安装首启、Docker 镜像、URL Rewrite、反向代理安全、`data` 目录防暴露和 healthcheck 检查补到静态复现里。本轮不做真实部署，只把管理员在上线前需要确认的部署条件产品化表达出来。

## 官网依据
- Installation Instructions: 安装前要确认 requirements，首启后要修改默认 `admin/admin`，并阻止 `data` 目录通过 URL 暴露；Archive 安装需要确认 `data` 目录可写。
- Docker Image Usage: 官方镜像有 Docker Hub、GHCR、Quay 三类 Registry；推荐固定具体版本；常用持久化卷包括 `/var/www/app/data`、`/var/www/app/plugins`、`/etc/nginx/ssl`；配置可通过环境变量或 data 卷里的 `config.php`；v1.2.46 起有 `healthcheck.php`。
- URL Rewriting: Kanboard 可启用或不启用 URL Rewrite；Apache 可自动检测，Nginx/IIS 等需要显式配置；同时要拒绝访问 `/data` 和隐藏文件。
- Reverse Proxy Authentication: 反向代理认证要防止 Header 伪造，代理应清理客户端传入的认证 Header，并且 Kanboard 需要配置 `TRUSTED_PROXY_NETWORKS`。
- Security: 官网强调默认密码、data 目录保护、反向代理 Header 清理、登录限流、Webhook/插件/外链出站访问限制和插件来源验证。

## 本轮新增
- 顶部新增 `部署检查` 入口，作为安装部署和访问安全的系统级检查台。
- 新增 `state.deployment.install`，记录安装方式、版本、安装路径、访问地址、默认密码是否修改、data 目录是否保护、`.htaccess/web.config` 是否生效、data 目录是否可写、是否安装在 DocumentRoot 之外、是否确认 requirements。
- 新增 `state.deployment.docker`，记录 Docker 是否启用、Registry、Image Tag、是否固定版本、data/plugins/ssl Volume、环境变量配置、data 卷 config.php、healthcheck、Compose 数据库方案、Docker 邮件传输规划。
- 新增 `state.deployment.access`，记录 Web Server、URL Rewrite、子目录、data deny、隐藏文件 deny、反向代理、是否阻止直连、是否清理认证 Header、是否覆盖 X-Forwarded Header、可信代理网段、X-Forwarded-Proto、限流和出站网络限制。
- 新增部署风险面板，覆盖默认密码、data 暴露、Docker latest/nightly、Volume 缺失、healthcheck 缺失、Docker 邮件方式、Nginx/IIS Rewrite、反向代理可信网段、Header 伪造、登录限流和 SSRF 出站风险。
- 新增部署 Runbook 预览，生成安装参数、URL Rewrite、反向代理加固和 Docker 命令片段。
- 新增模拟 `healthcheck.php`，根据 Docker 与 data volume 状态写入 `200 OK` 或 `503 Service Unavailable` 日志。
- 将 localStorage key 升级为 `kanboard-static-v0822`，项目 JSON 导出版本同步为 `kanboard-static-v0822`。

## 产品判断
- 这部分属于上线前的部署验收，不应混在项目看板或任务卡片里，应与 `运行环境`、`运维任务`、`系统设置` 并列。
- `运行环境` 解决“PHP/数据库是否能跑”，`部署检查` 解决“实例如何被安装、暴露、代理和监控”，两者职责相邻但不重复。
- Healthcheck 是 Kubernetes/容器化场景常见验收点，因此在静态复现里用模拟日志表达，不真实请求本机服务。
- 风险提示要覆盖安全暴露面，因为 Kanboard 官网反复强调默认密码、data 目录和反向代理 Header 是上线风险。
