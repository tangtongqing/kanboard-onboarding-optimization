# 运行环境、数据库与升级检查补齐说明 V0.8.21

## 本轮目标
继续对照 Kanboard 官网管理端能力，把“能跑起来”背后的系统级配置补到静态复现里。本轮新增的是运行环境控制台，覆盖数据库驱动、PHP 扩展、存储路径、缓存、URL Rewrite、SQLite 备份优化、数据库迁移和升级前检查。

## 官网依据
- Requirements and Prerequisites: Kanboard 当前要求 PHP >= 8.1，并列出 SQLite、MySQL/MariaDB、PostgreSQL 和必需 PHP 扩展。
- Configuration File: Kanboard 通过 `config.php` 或环境变量配置 `DB_DRIVER`、`DB_RUN_MIGRATIONS`、`DB_WAL_MODE`、`FILES_DIR`、`CACHE_DRIVER`、`ENABLE_URL_REWRITE`、`DEBUG` 等选项。
- SQLite: Kanboard 默认使用 `data/db.sqlite`，支持从设置菜单下载数据库，也可通过 `VACUUM` 优化；v1.2.27 后默认开启 WAL。
- Upgrading to a New Version: 升级前应备份并验证数据、阅读 ChangeLog、停止 Worker、进入维护模式、清理会话；数据库迁移默认自动执行，也可用 `./cli db:migrate` 手动执行。
- Performance Optimization: 高并发场景不建议继续使用 SQLite，应考虑 PostgreSQL 或 MySQL，并开启 OpCode 缓存。

## 本轮新增
- 顶部新增 `运行环境` 入口，作为系统级配置与部署检查面板。
- 新增 `state.runtime.database`，记录数据库驱动、SQLite 文件、远程数据库主机/端口/库名/用户名、WAL 模式、自动迁移、Schema 版本、备份时间和优化时间。
- 新增 `state.runtime.environment`，记录 PHP 版本、Web Server、安装方式、部署场景、data 目录可写、FILES_DIR、缓存驱动、缓存目录可写、OpCode 缓存、URL Rewrite 和 DEBUG。
- 新增 `state.runtime.php.extensions`，按当前数据库驱动动态检查核心 PHP 扩展和对应 PDO 扩展。
- 新增 `state.runtime.upgrade`，把升级前准备事项做成可勾选清单：ChangeLog、备份验证、停止 Worker、维护模式、清理会话、插件兼容。
- 新增运行环境风险提示：PHP 版本过低、缺少 PDO 扩展、SQLite 用于 Docker/NFS/高可用场景、目录不可写、文件缓存不可写、未开启 OpCode、生产开启 DEBUG、迁移前缺少备份、升级前未停 Worker 或未开维护模式。
- 新增 `config.php` 预览，把 UI 配置映射到 Kanboard 的配置常量。
- 新增模拟数据库备份、模拟运行迁移、模拟优化数据库，并写入操作日志。
- 将 localStorage key 升级为 `kanboard-static-v0821`，项目 JSON 导出版本同步为 `kanboard-static-v0821`。

## 产品判断
- 这部分不是普通项目管理功能，而是实例级管理员能力，所以入口应与 `系统设置`、`运维任务` 同级，而不是放进单个项目设置。
- 静态复现不应该真的操作数据库，因此“备份、迁移、优化”都只做状态模拟和日志记录，重点是表达用户决策路径和风险反馈。
- 数据库驱动变化会影响必需扩展，所以扩展检查需要跟随 SQLite/MySQL/PostgreSQL 动态变化。
- 升级流程的关键不是“一个升级按钮”，而是升级前检查是否清晰；这更符合 Kanboard 文档里的运维约束。
