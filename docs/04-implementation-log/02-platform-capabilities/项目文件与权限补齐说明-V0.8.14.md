## 官网核对

Kanboard 的 Project Overview 包含项目描述、项目文档、项目成员和最新活动。官方 API 里也单独提供 Project File 和 Project Permission 相关能力，覆盖项目文件创建、列表、下载、删除，以及项目用户/用户组授权、移除和角色变更。

参考：

- Boards / Project Overview 文档：https://docs.kanboard.org/v1/user/boards/
- Project File API 文档：https://docs.kanboard.org/v1/api/project_file_procedures/
- Project Permission API 文档：https://docs.kanboard.org/v1/api/project_permission_procedures/

## 本轮补齐

### 1. 项目文件库

项目设置新增 `项目文件`：

- 可添加文件名或链接、类型/大小、负责人。
- 支持删除项目文件。
- 默认 PM 工作流项目内置需求调研、PRD、上线检查清单等资料。
- 个人学习项目默认生成学习路线和作品集素材清单。
- 项目活动流会展示项目文件记录。

### 2. 访问范围

项目属性新增 `访问范围`：

- 私有项目。
- 团队可见。
- 公开只读。

这不是后端权限校验，而是静态原型中对项目访问策略的产品表达。

### 3. 用户组权限

项目设置新增 `用户组权限`：

- 支持添加用户组。
- 支持设置管理员、成员、访客三类静态角色。
- 支持删除用户组。
- Overview 会汇总成员与用户组数量，并展示成员/用户组角色分布。

## 产品判断

项目文件承载的是项目级资料，例如 PRD、调研报告、上线清单和复盘材料；任务附件承载的是单个任务上下文。两者要分开，否则项目级沉淀会散落在任务详情里。

权限能力在静态原型阶段不适合模拟真实登录、鉴权和接口校验，但可以先把信息架构、角色关系和配置路径复现出来。这样进入 Figma 高保真时，项目设置、Overview 和后端边界都更清楚。
