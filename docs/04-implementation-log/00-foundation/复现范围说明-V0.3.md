# Kanboard MVP 复现范围说明 V0.3

| 项目 | 内容 |
|---|---|
| 版本 | V0.3 |
| 日期 | 2026-06-01 |
| 状态 | 开发中 |
| 目标 | 复现 Kanboard 的核心看板体验，为后续“新手创建向导”优化打基础 |

## 1. 为什么先复现

如果直接设计“模板向导”，容易变成一个脱离 Kanboard 本体的新产品。正确顺序应该是：

1. 先复现 Kanboard 的核心体验。
2. 在复现版中观察新手创建空白项目时的阻力。
3. 再加入新手创建向导和模板能力。
4. 对比优化前后的体验差异。

## 2. 你选出的核心功能

你给出的核心功能是：

1. 项目。
2. 任务卡片。
3. 卡片流转。

这个判断是准确的。Kanboard 的产品骨架就是：用户围绕一个项目，把任务卡片放在不同状态列中，并通过卡片流转表达工作进度。

## 3. V0.3 必做范围

| 模块 | 功能 | 说明 |
|---|---|---|
| 项目 | 创建项目 | 新建一个空白看板项目 |
| 项目 | 切换项目 | 左侧项目列表切换当前看板 |
| 项目 | 删除项目 | 删除非最后一个项目 |
| 看板列 | 新增列 | 用户可自定义状态列 |
| 看板列 | 重命名列 | 适配不同项目流程 |
| 看板列 | 删除列 | 删除列时移动或清理任务 |
| 任务卡片 | 新建任务 | 在任意列中新建任务 |
| 任务卡片 | 编辑任务 | 编辑标题、描述、负责人、分类、优先级、截止日期、标签 |
| 任务卡片 | 删除任务 | 从看板中移除任务 |
| 卡片流转 | 拖拽卡片 | 卡片可以拖到其他列 |
| 筛选 | 搜索/分类/负责人筛选 | 帮助用户在多任务时找到卡片 |
| 数据 | 本地保存 | 使用 localStorage 保存项目数据 |

## 4. V0.3 不做范围

| 功能 | 暂不做原因 |
|---|---|
| 登录/权限 | 属于多用户系统能力，超出前端 MVP |
| 复杂自动化 | Kanboard 重要能力，但不是新手创建体验的前置条件 |
| 插件系统 | 工程复杂度高，不适合作为第一阶段 |
| 服务端数据库 | 先用 localStorage 保证学习和演示效率 |
| 完整报表 | 后续作品集版可用静态指标替代 |

## 5. 后续优化接口

V0.3 复现版会故意保留一个“新建项目”入口。V0.4 将在这个入口上加入：

- 空白项目 / 从模板开始。
- 个人学习、求职准备、小团队迭代、Bug 跟踪模板。
- 模板预览。
- 自动生成列和示例卡片。

这样后续优化不是另起炉灶，而是嵌入 Kanboard 的核心使用路径。
