# 双智能体文件中转协作方案

## 1. 工作流基线

本项目以全局 `product-design-workflow` 为总工作流，规范源文件为：

`C:\Users\tangtongqing\.codex\skills\product-design-workflow\SKILL.md`

本文件只定义总工作流中的 **Dual-Agent File Handoff Gate**，不是完整 Product Design Workflow 的替代品。

| 层级 | 本项目采用方式 |
|---|---|
| 产品策略与需求输入 | 使用 PM 方法完成问题定义、研究、PRD、用户故事和优先级；对应 PD-001~PD-004 |
| UI/UX 核心设计 | 使用 `impeccable`；本项目属于 SaaS / 管理工具界面，register 固定为 `product` |
| 设计准备与规格 | 流程、IA、状态、原则、页面 Brief 和设计系统；对应 PD-005~PD-009 |
| 低保真与方案成形 | PD-010 使用 `impeccable shape`，先确认结构、路径和关键状态，不直接写业务代码 |
| 高保真与实现 | PD-011 使用 `impeccable craft`；有明确 brief 和已确认线框后再进入 Figma 或前端实现 |
| 质量闭环 | 使用 `critique`、`audit`，必要时再执行 `polish`、`harden`、`adapt` |
| 双智能体执行 | 使用本文件定义的 inbox / outbox 文件中转，由 Codex 最终验收 |

历史 PD-001~PD-009 的完成状态表示产物已通过项目验收，不反向宣称曾运行未留证据的 `impeccable` 命令。后续任务单必须记录实际使用的 Product Design 阶段、register、工具和验收证据。

## 2. 协作目标

本项目改为最简单稳定的文件中转模式：

```text
Codex 写任务单
-> Mimo Code 读取任务单并执行
-> Mimo Code 写结果文件
-> Codex 验收结果
-> Codex 决定通过、返工或亲自接手
```

不再使用自动化 CLI、server、attach、trace、progress 或可视化终端方案。

## 3. 目录约定

```text
.agent-ops/
  mimo/
    inbox/      # Codex 发布任务
    outbox/     # Mimo Code 写回结果
    archive/    # 完成任务归档
```

## 4. 角色分工

### Codex

- 读取项目上下文。
- 按 `product-design-workflow` 判断任务边界、设计要求、测试要求和安全门禁。
- 写入结构化任务单。
- 审查 Mimo Code 的结果、代码 diff、测试输出和风险说明。
- 向用户汇报最终结论。

### Mimo Code

- 只读取 `inbox/` 中最新任务单。
- 只在任务允许的文件范围内工作。
- 完成后把结果写入任务指定的 `outbox/` 文件。
- 不自行扩大范围，不做未被授权的重构。
- 遇到阻塞时写入结果文件，交由 Codex 判断。

### 用户

- 只和 Codex 沟通目标与验收感受。
- 需要执行 Mimo Code 时，把固定启动语交给 Mimo Code。

## 5. 固定启动语

给 Mimo Code 使用：

```text
你是本项目的执行智能体。请只读取 .agent-ops/mimo/inbox 中最新任务单，并严格按任务要求工作。
完成后把结果写入任务单指定的 .agent-ops/mimo/outbox 文件。
不要自行扩大范围；遇到不确定、测试失败、权限/安全风险时，把问题写入结果文件，不要自己猜。
```

## 7. 验收规则

Codex 验收时按顺序检查：

1. 是否完成任务目标。
2. 是否越界修改。
3. 是否符合当前产品设计与项目路线。
4. 是否影响 `localStorage` 版本、导入导出版本或测试数据。
5. 是否补充必要测试。
6. 是否运行任务指定命令。
7. 涉及 API、认证、权限、安全、文件、部署时，是否满足静态原型安全门禁。
8. 涉及产品设计文档时，是否明确标注“假设版 / 待研究验证版”，避免把研究计划写成研究结论。
9. 涉及 Mermaid、流程图、状态图、线框结构图时，Mimo Code 只交付 Markdown 与 Mermaid 源码；Codex 在验收阶段负责导出 PNG/SVG 或调用相应设计工具。
10. 涉及后续 Product Design / Figma / 高保真工作时，必须先有页面级 brief、视觉目标或明确的设计输入，不能直接从空泛描述进入高保真。
11. 涉及 UI/UX 时，是否记录 `product-design-workflow` 路由、register、实际使用的 `impeccable` 阶段和对应证据。
