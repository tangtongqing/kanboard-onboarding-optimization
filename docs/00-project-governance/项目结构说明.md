# 项目结构说明

本文档定义当前仓库的目录职责，避免 Markdown 文档再次堆回项目根目录。

## 根目录

| 路径 | 职责 |
|---|---|
| `README.md` | 项目总览、当前状态、关键入口 |
| `PRODUCT.md` | `product-design-workflow` / `impeccable` 使用的产品战略上下文；记录 register、用户、目的、原则与无障碍边界 |
| `index.html` | 本地静态产品原型入口；发布时映射为 `app.html` |
| `styles.css` | 静态原型样式 |
| `app.js` | 静态原型交互逻辑 |
| `product.html`、`product.css`、`product.js` | 面向用户的营销首页源文件与交互 |
| `pricing.html`、`contact.html`、`marketing-pages.*` | 价格计划、联系页面及共享样式与交互 |
| `landing.html`、`landing.css`、`landing.js` | 面向面试官的设计案例页及交互 |
| `assets/` | 营销页视频等媒体资产 |
| `scripts/build-pages.mjs` | 生成 GitHub Pages 发布包 |
| `.github/workflows/deploy-pages.yml` | `main` 分支自动构建与发布工作流 |
| `tests/` | 自动化验收脚本 |
| `设计图/` | 页面截图、流程图、状态图、设计图导出资产 |
| `docs/` | 项目文档中心 |

根目录不再新增普通说明类 Markdown 文件。除 `README.md` 和 Product Design 工具要求的 `PRODUCT.md` 外，新的 Markdown 应进入 `docs/` 对应目录。

## docs 目录

| 目录 | 放置内容 |
|---|---|
| `docs/00-project-governance/` | 启动说明、路线图、真实进度基线、协作方案、项目结构、版本记录 |
| `docs/01-research-discovery/` | 竞品分析、用户研究、问题定义、机会说明 |
| `docs/02-requirements/` | PRD、用户故事、验收标准、需求拆解 |
| `docs/03-ux-design/` | 流程图、信息架构、交互状态、设计原则、页面级设计 brief |
| `docs/04-implementation-log/` | 静态原型实现迭代说明、功能补齐与线上发布记录 |
| `docs/05-validation/` | 静态功能验收报告、测试结论 |

## Product Design 文档归档规则

| 任务类型 | 推荐目录 |
|---|---|
| 产品机会、问题定义、用户研究计划 | `docs/01-research-discovery/` |
| PRD、用户故事、验收标准 | `docs/02-requirements/` |
| 流程、IA、状态、设计原则、线框 / 高保真前置 brief | `docs/03-ux-design/` |
| 可用性测试计划与结论 | `docs/05-validation/` 或后续独立研究目录 |

## 本地工具边界

| 路径 | 处理规则 |
|---|---|
| `.agent-ops/` | 智能体协作中间文件，不属于最终交付仓库 |
| `.mimocode/` | Mimo Code 本地客户端工作区，不属于项目交付物 |
| `.impeccable/` | 本地工具运行配置与会话缓存，不属于项目交付物 |
| `scratch/` | 一次性截图、检查脚本与临时实验，不进入最终归档 |
| `*.log`、`*.tmp` | 运行日志和临时文件，不进入最终归档 |
| `dist-pages/` | 构建脚本生成的 GitHub Pages 发布包；不提交，由部署工作流即时生成 |

## 设计图资产规则

- Mermaid 源码保留在对应 Markdown 文档中。
- Codex 导出的 PNG / SVG 放入 `设计图/PD-xxx/`。
- 产品界面截图继续放在 `设计图/` 根层，文件名使用版本号和页面名。
- 不在 `docs/` 内混放图片产物，避免文档和设计资产职责混乱。

## 新增文件检查

新增文件前先判断：

1. 是否影响静态原型运行？如果是，放在根目录或 `tests/`。
2. 是否是产品设计、需求、研究或复盘文档？如果是，放入 `docs/` 对应目录。
3. 是否是智能体协作过程产物？如果是，默认不进入最终归档；必要结论应沉淀到 `docs/`。
4. 是否是截图、流程图、状态图或设计图？如果是，放入 `设计图/`。
5. 是否是本地依赖、缓存或 QA 中间产物？如果是，按 `.gitignore` 排除，不作为项目交付物提交。
