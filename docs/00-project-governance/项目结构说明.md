# 项目结构说明

本文档定义当前仓库的目录职责，避免 Markdown 文档再次堆回项目根目录。

## 根目录

| 路径 | 职责 |
|---|---|
| `README.md` | 项目总览、当前状态、关键入口 |
| `PRODUCT.md` | `product-design-workflow` / `impeccable` 使用的产品战略上下文；记录 register、用户、目的、原则与无障碍边界 |
| `index.html` | 静态原型入口 |
| `styles.css` | 静态原型样式 |
| `app.js` | 静态原型交互逻辑 |
| `tests/` | 自动化验收脚本 |
| `设计图/` | 页面截图、流程图、状态图、设计图导出资产 |
| `docs/` | 项目文档中心 |
| `.agent-ops/` | Codex 与 Mimo 的任务中转、回传、验收记录和可复现设计图渲染工具 |
| `.mimocode/` | Mimo Code 本地客户端工作区；不属于项目交付物，整目录忽略 |
| `.impeccable/` | `impeccable` 项目配置；live 会话和运行时缓存按工具规则管理 |

根目录不再新增普通说明类 Markdown 文件。除 `README.md` 和 Product Design 工具要求的 `PRODUCT.md` / `DESIGN.md` 外，新的 Markdown 应进入 `docs/` 或 `.agent-ops/`。

## docs 目录

| 目录 | 放置内容 |
|---|---|
| `docs/00-project-governance/` | 启动说明、路线图、真实进度基线、协作方案、项目结构、版本记录 |
| `docs/01-research-discovery/` | 竞品分析、用户研究、问题定义、机会说明 |
| `docs/02-requirements/` | PRD、用户故事、验收标准、需求拆解 |
| `docs/03-ux-design/` | 流程图、信息架构、交互状态、设计原则、页面级设计 brief |
| `docs/04-implementation-log/` | 静态原型实现迭代说明、功能补齐记录 |
| `docs/05-validation/` | 静态功能验收报告、测试结论 |

## Product Design 文档归档规则

| 任务类型 | 推荐目录 |
|---|---|
| 产品机会、问题定义、用户研究计划 | `docs/01-research-discovery/` |
| PRD、用户故事、验收标准 | `docs/02-requirements/` |
| 流程、IA、状态、设计原则、线框 / 高保真前置 brief | `docs/03-ux-design/` |
| 可用性测试计划与结论 | `docs/05-validation/` 或后续独立研究目录 |
| Mimo 任务单 | `.agent-ops/mimo/inbox/` |
| Mimo 回传与 Codex 验收记录 | `.agent-ops/mimo/outbox/` |

## 本地工具边界

| 路径 | 处理规则 |
|---|---|
| `.agent-ops/render-tools/*.cjs`、配置文件、`package.json`、锁文件 | 可复现 Mermaid 导出所需工具，属于项目工具资产 |
| `.agent-ops/render-tools/node_modules/` | 本地依赖，可通过锁文件恢复，不进入 Git |
| `.agent-ops/render-tools/sources/` | 从 Markdown 临时抽取的 Mermaid 源文件，不进入 Git；权威源码仍在对应文档中 |
| `.agent-ops/render-tools/qa/` | 联系表等目视检查中间产物，不进入 Git；正式 PNG/SVG 放入 `设计图/` |
| `.mimocode/` | Mimo Code 本地插件和工作流副本，不进入 Git；协作规范以全局 `product-design-workflow` 和项目治理文档为准 |

## 设计图资产规则

- Mermaid 源码保留在对应 Markdown 文档中。
- Codex 导出的 PNG / SVG 放入 `设计图/PD-xxx/`。
- 产品界面截图继续放在 `设计图/` 根层，文件名使用版本号和页面名。
- 不在 `docs/` 内混放图片产物，避免文档和设计资产职责混乱。

## 新增文件检查

新增文件前先判断：

1. 是否影响静态原型运行？如果是，放在根目录或 `tests/`。
2. 是否是产品设计、需求、研究或复盘文档？如果是，放入 `docs/` 对应目录。
3. 是否是 Mimo / Codex 协作过程产物？如果是，放入 `.agent-ops/`。
4. 是否是截图、流程图、状态图或设计图？如果是，放入 `设计图/`。
5. 是否是本地依赖、缓存或 QA 中间产物？如果是，按 `.gitignore` 排除，不作为项目交付物提交。
