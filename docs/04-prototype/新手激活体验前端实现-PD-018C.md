## 2. Onboarding Checklist 状态机

### 2.1 存储机制
浮窗状态与当前活跃项目的 `projectId` 绑定，存储于 `localStorage` 中。
- **Key**：`kanboard:onboarding-checklist:{projectId}`
- **数据结构**：
  ```json
  {
    "shown": true,
    "dismissed": false,
    "collapsed": false,
    "completed": {
      "editExampleCard": false,
      "dragCardRight": false,
      "createRealCard": false
    },
    "createdAt": "2026-06-30T06:22:00.000Z",
    "updatedAt": "2026-06-30T06:23:00.000Z"
  }
  ```

### 2.2 触发条件与容错机制
1. **修改示例卡片 (editExampleCard)**：
   - *标准判定*：双击修改带有 `isExample: true` 标记的示范卡片（匹配 `【学习示范】` 或 `【求职示范】` 等标题前缀）并保存成功。
   - *Fallback 保底*：若用户在修改前已删光了所有示例卡，系统通过 `allCards()` 检测其数量，发现为 0 时自动自适应把清单文案修改为 `“在看板任意列双击创建一张新卡片”`，双击编辑并保存任何卡片即可使其通过，避免死锁。
2. **拖动流转 (dragCardRight)**：
   - *标准判定*：卡片拖放放置成功时，校验目标列在项目 `columns` 数组中的 index **大于** 原起始列 of index。WIP 限制导致的弹回失败不予计入。
3. **新建卡片 (createRealCard)**：
   - *标准判定*：在最左侧首列创建任务，校验标题不为空，且不带有“示例”、“示范”、“占位”等系统保留字符。

## 3. Tooltip 帮助术语字典与定位算法

### 3.1 覆盖字典
为降低新手认知抗拒，对以下 10 个高频黑话/字段进行了绑定：
- `swimlane` (泳道)、`wipLimit` (WIP限制)、`assignee` (负责人)、`priority` (优先级)、`dueDate` (截止日期)、`category` (分类)、`tags` (标签)、`estimate` (预估工时)、`spent` (实际工时)、`blockRisk` (阻塞 / 风险)。

### 3.2 自适应定位算法
在桌面端通过事件监听 `.help-icon-wrapper` 的 `mouseenter` 和 `focus` 触发：
1. **边界溢出防护**：利用 `getBoundingClientRect()` 计算气泡尺寸。默认在 `?` 图标上方弹出（CSS arrow-bottom 指向）。
2. **顶边缘检测**：若距离屏幕顶部高度小于气泡高度，自动翻转朝向切换为在下方弹出（CSS arrow-top 指向）。
3. **侧边缘检测**：若气泡最右侧超出当前浏览器 `window.innerWidth` 视口，自动向左偏置对齐，保持留有 `12px` 的安全边距，防止文字溢出裁剪。

## 4. 本地模拟埋点系统

提供全流程埋点事件流以支撑激活转化漏斗分析。
- **Key**：`kanboard:activation-events`（以 JSON 数组形式追加保存）
- **载荷格式**：
  ```json
  {
    "eventName": "example_card_edit_save",
    "payload": {
      "projectId": "project-123",
      "cardId": "card-456",
      "oldTitle": "【学习示范】理解产品经理职责",
      "newTitle": "整理产品职责思维导图",
      "timestamp": "2026-06-30T06:22:50.000Z"
    }
  }
  ```
- **支持的事件映射**：
  - `activation_checklist_shown`：Checklist 首次淡入呈现
  - `activation_checklist_expand`：用户折叠/展开 Checklist
  - `activation_checklist_item_complete`：任意单项任务打勾
  - `activation_checklist_all_complete`：新手破冰三项全部通关
  - `activation_checklist_dismiss`：点击“永久隐藏”或“我知道了”关闭浮窗
  - `example_card_open`：双击打开示例卡详情弹窗
  - `example_card_edit_save`：保存了对示例卡（或 fallback 卡）的标题修改
  - `example_card_delete`：删除了示例卡片
  - `field_help_open`：触发了某个术语帮助 Tooltip
  - `field_help_close`：关闭了术语帮助 Tooltip
  - `first_card_drag`：成功把卡片往右拖拽了一列
  - `first_real_card_create`：在首列创建了非占位真实任务卡

## 5. 已知限制与给 PD-018D 的测试点

### 5.1 已知限制
- **移动端 Tooltip 互斥**：在小于等于 `480px` 的视口下，Tooltip 取消了 `:hover` 伪类触发（避免触控粘连），改为 `click` 切换。单次最多仅允许屏幕中浮现一个气泡，点击任何空白背景即可关闭。
- **重置联动**：重置演示数据将清空 localStorage 中全部项目的 `kanboard:onboarding-checklist:*` 缓存，模板新建项目重置后可以重新被唤醒。

### 5.2 给 PD-018D 的自动化测试建议 (Playwright 路径)
1. **Checklist 弹出路径**：
   - 步骤：使用“使用场景模板”新建一个项目；
   - 断言：检测 `#onboarding-checklist` 存在，且进度为 `0/3`；
   - 步骤：直接空白创建新项目；
   - 断言：检测 `#onboarding-checklist` 不存在。
2. **任务联动断言**：
   - 双击带 `isExample` 的卡片，修改标题并点击保存，断言 Checklist 打勾，埋点日志出现 `example_card_edit_save`。
   - 拖拽卡片从 Col 0 到 Col 1，断言 Checklist 打勾，埋点日志出现 `first_card_drag`。
   - 点击首列 `+` 新建任务“自测试”，断言 Checklist 进度达到 `3/3` 并浮现成功面板。
3. **无障碍焦点**：
   - 按 `Tab` 键应能依次聚焦至 Checklist 头部、关闭按钮和帮助问号 `?`。
   - 聚焦到帮助问号时，Tooltip 浮窗应自动展现；按 `Escape` 键应同时关闭当前打开的 Tooltip 或移动端 Drawer。
