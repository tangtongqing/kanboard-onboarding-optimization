> **版本性质**：首次核心操作轻引导用户故事与数据规范（需求阶段，不做实现）  
> **更新日期**：2026-07-03  
> **当前项目生命周期阶段**：下一轮增量规划阶段  

---

## 1. 交互状态机定义

引导项目状态持久化记录于 `localStorage`，采用 key 为：`kanboard:first-action-guidance:{projectId}` 的数据格式。

### 状态值定义 (State Values)
*   **`not_seen`** (默认)：该引导项从未向用户展示过。
*   **`shown`**：引导项已触发并在页面中呈现实时浮层，但用户尚未发生目标交互或点击关闭。
*   **`dismissed`**：用户点击了气泡上的“我知道了”或“关闭”，引导永久不再触发。
*   **`completed`**：用户已经成功完成了该操作挑战，引导永久不再触发。
*   **`suppressed`**：因为有更高级别的全局组件（如 Checklist 抽屉、活动 Dialog）处于激活状态，为了防止视觉重叠，本次气泡展现被暂时抑制。

### 离线数据存储样例 (localStorage Schema)
```json
{
  "dragCard": "completed",
  "editCard": "completed",
  "deleteCard": "dismissed",
  "taskMenu": "shown",
  "updatedAt": "2026-07-03T01:20:00.000Z"
}
```

## 2. 用户故事与验收标准

### Story 1: 首次卡片拖拽轻提示
*   **用户故事**：作为新手，我第一次拖动卡片成功后，希望知道任务已经进入下一个阶段，以建立推进进度的踏实感。
*   **触发前置条件**：
    1. 该项目为场景模板项目，或为用户已创建了第一张真实卡片的空白项目；且 `localStorage` 中 `dragCard` 的状态为 `not_seen`。
    2. 用户将光标 Hover 在任意卡片（卡片此时处于“待学”或“待办”列）超过 0.8 秒。
    3. 页面无任何激活打开的 Dialog 或已展开的 Checklist Drawer。
*   **交互规则**：
    1. 在该卡片上方正中弹出一个带指示针的轻量级 Popover，背景色为深灰偏蓝（无强视觉打扰），显示文字：“您可以随时把卡片向右侧列拖动，以推进任务状态。”
    2. 气泡上提供一个“我知道了”的极小文字关闭链接。
    3. 一旦用户按下鼠标开始拖拽该卡片，或者点击“我知道了”，气泡渐隐消失，并且更新 `dragCard` 的状态为 `completed`（或 `dismissed`）。
*   **验收标准**：
    1. 悬停 0.8 秒后气泡正常显示，若用户移开鼠标但未发生点击或拖动，气泡保持显示（此时状态更新为 `shown`）。
    2. 一旦检测到 `dragstart` 事件，气泡在 0.15 秒内渐隐，数据写入 `completed`，用户刷新页面后再次悬停不再显示。
*   **埋点事件**：
    *   `first_action_guidance_shown` (payload: `{ field: "dragCard", projectId }`)
    *   `first_action_guidance_completed` (payload: `{ field: "dragCard", projectId }`)
*   **边界状态**：
    *   若在气泡展示期间，用户点击了系统顶栏的“新建项目”按钮打开了 Dialog，气泡必须立刻强制销毁（状态更新为 `suppressed`），并在下一次重新进入看板且符合条件时再显示。

### Story 2: 首次卡片双击编辑轻提示
*   **用户故事**：作为新手，我第一次双击编辑示例卡后，希望得到温馨说明，知道这张示例卡已经变成我的真实任务，以减少不敢碰模板的焦虑。
*   **触发前置条件**：
    1. 该项目为场景模板项目（基于内置示例卡触发），或为用户已创建了第一张真实卡片的空白项目（基于该卡片触发）；且 `localStorage` 中 `editCard` 状态为 `not_seen`。
    2. 页面中首个“学习示范”卡片（或空白项目创建的首张真实卡片）加载到看板中。
*   **交互规则**：
    1. 在第一张示例任务卡卡片标题旁边展示一个呼吸状的小红点（或微动效）。
    2. 用户悬停该卡片时，上方浮现小气泡：“双击可修改我的内容与完成标准，变成你的真实任务。”
    3. 用户双击该卡片拉起卡片编辑 Dialog，气泡消失，状态更新为 `completed`。
*   **验收标准**：
    1. 正常双击打开 Dialog 后，气泡彻底移除并销毁。
    2. 刷新页面再次访问此项目，已修改过或已被激活的卡片不再出现小红点与悬停气泡。
*   **埋点事件**：
    *   `first_action_guidance_shown` (payload: `{ field: "editCard", projectId }`)
    *   `first_action_guidance_completed` (payload: `{ field: "editCard", projectId }`)
*   **边界状态**：
    *   若用户直接把这张卡片拖拽到了其他列而没有执行双击，该引导判定用户已经理解了“卡片可控性”，`editCard` 自动标记为 `completed` 并不再显示。

### Story 3: 首次触发删除防误删确认
*   **用户故事**：作为新手，我第一次准备删除卡片时，希望知道删除操作会移除什么、是否能找回，以此打消删除导致的心理压力。
*   **触发前置条件**：
    1. `localStorage` 中整个浏览器的 `deleteCard` 状态为 `not_seen`。
    2. 用户在卡片详情或任务菜单中点击了“删除任务”按钮。
*   **交互规则**：
    1. 系统拦截默认的卡片直接删除行为（或拦截原生 `confirm()`），改弹出专属的轻量卡片提示层。
    2. 提示内容：“删除会彻底移除此卡片，本地数据不可恢复。这是你第一次进行删除操作，确认继续吗？”
    3. 提供“取消删除”（高亮主按钮）与“确认删除”（红色次按钮）。
    4. 无论点击取消还是确认，状态均转为 `completed`，下一次删除相同项目内其他卡片时不再拦截（直接使用普通轻提示或无确认逻辑）。
*   **验收标准**：
    1. 首次点击删除时，确认框拦截成功。
    2. 点击“取消删除”后，卡片保留，埋点正确记录取消，确认框关闭。
    3. 点击“确认删除”后，卡片在看板上移除，且刷新后不再显示该卡。
    4. 第二次删除卡片时，应当直接执行或调取常规提示，不再展示本防误删说明。
*   **埋点事件**：
    *   `first_delete_confirm_viewed` (payload: `{ cardId, projectId }`)
    *   `first_delete_cancelled` (payload: `{ cardId, projectId }`)
    *   `first_delete_confirmed` (payload: `{ cardId, projectId }`)
*   **边界状态**：
    *   若用户删除了唯一的卡片导致看板为空，此时如果新手激活 Checklist 尚未完成， Checklist 的“新建一张真实任务卡”需确保可以通过空看板的引导文案正常触发。

### Story 4: 高级用户与主动关闭用户零打扰
*   **用户故事**：作为高级/老用户，我拥有完整的看板使用经验，或者我作为一个已经手动关闭过提示的用户，不希望在工作中受到任何引导打扰。
*   **触发前置条件**：
    1. 用户在操作气泡上主动点击了“我知道了”或“关闭”（状态写入 `dismissed`）。
    2. 或用户之前已经在看板中完成过相应核心操作（状态写入 `completed`）。
    3. 或全局设定或点击了“不再提示”。
*   **交互规则**：
    1. 空白项目创建成功后不立即展示轻引导；但它绝不默认将所有引导状态机项初始化为 `dismissed`。只有当空白项目用户创建第一张真实卡片后，若对应状态仍为 `not_seen`，才允许在其首次拖拽、编辑、删除或操作任务菜单时触发轻引导。
    2. 对于已被标记为 `dismissed` 或 `completed` 的引导项，系统禁止向用户的 DOM 中挂载任何相关的 Popover、提示、呼吸红点或首次删除拦截弹层，确保零打扰。
*   **验收标准**：
    1. 在空白项目中 Hover 任何卡片，均无任何轻引导气泡出现。
    2. 进行卡片删除操作时，直接执行普通删除逻辑，无首次拦截说明弹层。
*   **埋点事件**：
    *   无
*   **边界状态**：
    *   老用户在空白项目中新建列并设置 WIP 限制时，点击 Label 旁边的小问号（Help Icon），**应当正常展示 Tooltip 大白话释义**（字段帮助属于功能性微文案，对老用户也可见，不属于打扰型新手教程）。

### Story 5: 移动端自适应排版
*   **用户故事**：作为移动端用户，当我在 <= 480px 的手机视口使用时，我希望轻引导气泡不会遮挡底部的 Checklist Drawer、卡片标题和主要提交按钮。
*   **触发前置条件**：
    1. 页面处于手机视口环境下（触发条件：`window.innerWidth <= 480px`）。
    2. 符合操作轻引导的前置触发条件。
*   **交互规则**：
    1. 移动端取消悬浮（Hover）触发机制，轻引导改为在符合前置条件时，在卡片主体下方露出小横条提示，或轻触才弹出气泡。
    2. 提示气泡的 z-index 设定为 `90`，必须低于 Checklist Drawer 的背景遮罩层（z-index: 100），当 Drawer 划出时，气泡自动隐藏并标记为 `suppressed`。
    3. 气泡自动避让底部动作菜单，优先向上或向页面中轴定位。
*   **验收标准**：
    1. 在 390px 视口下调试时，卡片气泡引导出现时看板没有溢出横向滚动条。
    2. 触控弹出清单 Drawer 后，底部的气泡自动隐藏，Drawer 关闭后重新显现（若操作未完成）。
*   **埋点事件**：
    *   `first_action_guidance_suppressed` (payload: `{ field, reason: "mobile_drawer_open", projectId }`)
*   **边界状态**：
    *   移动端发生双击操作时往往容易触发页面缩放，需确保在双击打开编辑弹窗时，气泡能在弹窗显示之前先隐藏。

### Story 6: 本地模拟埋点审计支持
*   **用户故事**：作为产品经理，我希望能获取这些首次核心操作引导的真实转化埋点，以衡量新手的引导流失，为产品优化提供客观数据支撑。
*   **触发前置条件**：
    1. 用户在看板上触发了轻引导的显示、关闭、完成、拦截或取消行为。
*   **交互规则**：
    1. 每次事件发生时，JS 将事件及 payload 数据结构（含 projectId、事件名、高精度 ISO 8601 时间戳）封装。
    2. 自动 push 进本地 `localStorage` 的 `kanboard:activation-events` 数组中。
    3. 此埋点数组与 `PD-018` 所用的埋点数组合并共用，确保统一的数据源读取。
*   **验收标准**：
    1. 在控制台运行 `localStorage.getItem("kanboard:activation-events")` 读出完整的事件流。
    2. 自动测试脚本在模拟拖拽后，可直接在该数组中查询到对应的 `first_action_guidance_completed` 埋点记录。
*   **埋点事件**：
    *   `first_action_guidance_shown`
    *   `first_action_guidance_dismissed`
    *   `first_action_guidance_completed`
    *   `first_action_guidance_suppressed`
*   **边界状态**：
    *   为防本地埋点无限累加撑爆 `localStorage` 空间，设定埋点条数安全防线：当数组长度达到 100 条时，自动剔除最早的 10 条事件。

## 3. 本地模拟埋点事件字典清单

| 事件名称 (Event Name) | 触发时机 (Trigger Condition) | Payload 属性定义 | 隔离属性 | 是否限一次 | 与 PD-018 关系 |
|---|---|---|---|---|---|
| **`first_action_guidance_shown`** | 首次轻引导气泡在看板中成功展示时 | `{ "field": "dragCard"/"editCard"/"taskMenu", "projectId": "..." }` | 按项目 projectId 隔离 | 是 | 写入统一的埋点库，序列号顺延 |
| **`first_action_guidance_dismissed`** | 用户点击气泡的“我知道了”或“关闭”时 | `{ "field": "dragCard"/"editCard"/"taskMenu", "projectId": "..." }` | 按项目 projectId 隔离 | 是 | 写入统一的埋点库 |
| **`first_action_guidance_completed`** | 用户成功发生拖动、双击或选择菜单动作时 | `{ "field": "dragCard"/"editCard"/"taskMenu", "projectId": "..." }` | 按项目 projectId 隔离 | 是 | 写入统一的埋点库 |
| **`first_action_guidance_suppressed`** | 气泡因为 Dialog 或 Drawer 开启而被迫避让隐藏时 | `{ "field": "...", "reason": "dialog_open"/"drawer_open", "projectId": "..." }` | 按项目 projectId 隔离 | 否 | 记录抑制状态，用于转化损耗分析 |
| **`first_delete_confirm_viewed`** | 首次点击卡片删除并弹出拦截说明框时 | `{ "cardId": "...", "projectId": "..." }` | 全局浏览器唯一触发 | 是 | 写入统一的埋点库，只记录一次 |
| **`first_delete_cancelled`** | 首次删除提示框中用户选择“取消删除”时 | `{ "cardId": "...", "projectId": "..." }` | 全局浏览器唯一触发 | 是 | 写入统一的埋点库 |
| **`first_delete_confirmed`** | 首次删除提示框中用户确认并执行卡片删除时 | `{ "cardId": "...", "projectId": "..." }` | 全局浏览器唯一触发 | 是 | 写入统一的埋点库 |
