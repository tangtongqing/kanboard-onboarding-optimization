## 1. 文档目的

本文档是 Kanboard "新手项目创建与任务拆解体验优化"的功能优化 PRD 骨架，目的是：

1. 将 PD-001 的问题定义、目标、成功指标、设计原则和非目标转成可评审的 PRD 结构。
2. 聚焦"新建项目到形成第一张可用看板"的核心路径，定义功能需求、交互要求和验收标准。
3. 为后续 PD-004 用户故事、PD-005 流程图和信息架构、PD-006 交互状态规格提供结构。
4. 作为假设版，明确标注待验证内容，后续可根据真实研究结论更新。

## 2. 背景与问题

### 背景

Kanboard 是一款经典开源看板式项目管理工具，优势是轻量、规则清楚、部署简单。但对新手来说，"轻"也可能意味着缺少场景化决策支持。新用户进入项目创建路径后，即使产品提供基础看板结构，也仍需要自己判断哪些列适合当前目标、写哪些任务、用什么粒度拆解。

### 用户问题

初次使用看板工具管理个人项目或小团队任务的用户，在第一次创建项目时可能不知道如何从模糊目标拆成可执行的任务列表。他们可能理解"看板"概念，但缺少从目标到列结构、从目标到任务粒度的具体拆解方法。

### 问题影响

- 新用户首次项目创建完成率可能偏低，可能在配置看板阶段放弃 `[待验证]`。
- 即使完成创建，看板结构也可能不符合当前场景需要 `[待验证]`。
- 字段含义缺少场景解释，用户不知道怎么填 `[待验证]`。
- 用户把工具当普通清单使用，没有理解看板流转的核心价值 `[待验证]`。

### 证据来源

| 证据 | 来源 | 置信度 |
|---|---|---|
| Kanboard 空白项目对新手不友好 | 竞品分析、用户假设 | 中（桌面研究） |
| Trello/Notion 模板能降低新手成本 | 竞品分析 | 中高（竞品验证） |
| 新手需要"在做中教"而不是"先教再做" | 竞品分析 | 中（竞品验证） |

## 3. 目标用户

### 用户A：作品集准备中的学生

- 背景：正在准备课程项目、竞赛或求职作品集
- 目标：把一个大项目拆成调研、方案、原型、复盘等任务
- 痛点：不知道第一张看板应该有哪些列，也不知道任务卡该写多细

### 用户B：个人开发者

- 背景：用自托管工具管理开源项目或个人产品
- 目标：管理需求、Bug、待办、发布计划
- 痛点：创建项目后还要手动建列、建分类、写示例任务，启动成本高

### 用户C：轻量团队负责人

- 背景：负责 2-5 人小团队的任务推进
- 目标：看清每个人的任务状态和阻塞点
- 痛点：不知道如何让团队统一任务状态和字段标准

## 4. 目标与成功指标

### 核心目标

缩短新用户从"进入产品"到"拥有一张可用看板"的路径，降低自行搭建看板结构带来的认知负担，让用户在第一次使用中理解 Kanboard 的基本工作流。

### 成功指标

#### 行为指标

| 指标 | 含义 | 预期变化 | 当前状态 |
|---|---|---|---|
| 首次项目创建完成率 | 新用户完成创建项目的比例 | 提升 | 无基线数据 `[待验证]` |
| 首次创建耗时 | 从点击新建到进入可用看板的时间 | 下降 | 无基线数据 `[待验证]` |
| 首次看板有效任务数 | 创建后 10 分钟内用户保留/新增的任务数 | 提升 | 无基线数据 `[待验证]` |
| 模板使用率 | 新项目中选择模板创建的比例 | 可观察 | 无基线数据 `[待验证]` |
| 示例卡删除/修改率 | 用户是否把示例卡转化为自己的任务 | 用于判断示例是否有用 | 无基线数据 `[待验证]` |

#### 体验指标

| 指标 | 含义 | 预期变化 | 当前状态 |
|---|---|---|---|
| 用户是否理解列结构 | 创建后用户能否正确使用列进行任务流转 | 提升 | 无基线数据 `[待验证]` |
| 用户是否能修改示例卡 | 用户能否将示例卡修改为自己的真实任务 | 提升 | 无基线数据 `[待验证]` |
| 用户是否理解字段含义 | 负责人、优先级、截止时间的填写正确率 | 提升 | 无基线数据 `[待验证]` |
| 用户是否理解看板流转 | 用户能否通过拖动卡片表达任务进展 | 提升 | 无基线数据 `[待验证]` |

## 5. 范围 In Scope

### 核心功能范围

| 功能 | 说明 | 优先级 |
|---|---|---|
| 新建项目入口升级 | 新建项目弹窗支持"空白项目"和"从模板开始"两种创建方式 | P0 |
| 场景模板选择 | 提供 4 个内置模板：个人学习、求职准备、小团队迭代、Bug 跟踪 | P0 |
| 模板预览 | 创建前可预览模板的列结构、泳道和示例任务卡 | P0 |
| 自动生成列结构 | 根据模板自动生成看板列（如待办/进行中/完成） | P0 |
| 自动生成示例任务卡 | 每个模板默认生成 3-5 张可删除示例任务卡 | P0 |
| 空白项目创建 | 保留原有空白创建路径，一键创建空项目 | P0 |
| 示例卡可修改 | 用户可修改示例卡的标题、描述、负责人、截止时间等 | P0 |
| 示例卡可删除 | 用户可删除不需要的示例卡 | P0 |
| 创建后进入看板 | 创建成功后直接进入已生成的可用看板 | P0 |

### 范围边界

- 只覆盖"新建项目到形成第一张可用看板"的路径，不涉及项目创建后的任务管理、协作、分析等能力。
- 模板是内置的，不支持用户创建自定义模板（P1 后续迭代）。
- 不支持模板编辑器（P2 后续迭代）。

## 6. 非范围 Out of Scope

| 不做的内容 | 理由 |
|---|---|
| 完整模板市场/模板商店 | 当前阶段只需要 4 个内置模板 |
| 多视图系统（日历、甘特、列表） | 已有静态演示资产，但偏产品增强，不属于新手创建核心 |
| 复杂自动化配置 | 属于进阶能力，不应进入新手创建向导 |
| 团队权限体系重构 | 属于系统级能力，不作为本次产品机会主线 |
| 登录注册和真实鉴权 | 静态原型项目 |
| API、Webhook、插件系统 | 已有静态演示资产，但属于开发者/运维能力，不进入本 PRD 范围 |
| 数据库、后台任务、Docker 部署 | 已有静态演示资产，但属于实例级运维能力，不进入本 PRD 范围 |
| 用户创建自定义模板 | P1 后续迭代 |
| 模板编辑器 | P2 后续迭代 |
| 字段微文案系统 | P1 后续迭代（PRD 可引用但不作为核心范围） |

## 7. 用户场景

### 场景1：学生从模板开始管理作品集

> 小明是一个正在准备求职作品集的学生。他第一次使用 Kanboard，点击"新建项目"，看到"从模板开始"选项。他选择"求职准备项目"模板，预览看到列结构（需求调研、方案设计、原型制作、复盘迭代）和 3 张示例任务卡。他点击"创建项目"，进入已生成的看板。他修改了第一张示例卡的标题为"整理作品集目录"，删除了不需要的示例卡，开始使用。

### 场景2：个人开发者从模板开始管理 Bug

> 小红是一个独立开发者，用 Kanboard 管理自己的开源项目。她点击"新建项目"，选择"从模板开始"，选择"Bug 跟踪"模板。预览看到列结构（待确认、修复中、待验证、已关闭）和示例任务卡。她创建项目后，把示例卡修改为自己的真实 Bug。

### 场景3：学生空白创建项目

> 小李是一个有经验的用户，他已经用过 Kanboard 管理过几个项目。他点击"新建项目"，直接选择"空白项目"，输入项目名称，一键创建。他不看到任何模板推荐，创建路径和原来一样快。

### 场景4：团队负责人从模板开始

> 小王是一个 3 人小团队的负责人。他点击"新建项目"，选择"从模板开始"，选择"小团队迭代"模板。预览看到列结构（待办、进行中、待评审、已完成）和示例任务卡。他创建项目后，把示例卡修改为团队的真实任务。

## 9. 功能说明

### 9.1 新建项目入口

**功能描述**：新建项目弹窗从单一入口升级为宽版创建向导，支持"空白项目"和"从模板开始"两种创建方式。

**交互说明**：
- 点击"新建项目"按钮，打开创建向导弹窗。
- 弹窗顶部展示两种创建方式的切换：「空白项目」和「从模板开始」。
- 默认选中策略为待验证设计选择：可默认选中「从模板开始」以强化新手引导，也可记忆上次选择以保护老用户效率，需结合 PD-002 研究结果决定。
- 老用户可快速切换到「空白项目」。

**状态说明**：
- 默认态：展示创建方式选择。
- 选择"空白项目"：展示项目名称和描述输入，一键创建。
- 选择"从模板开始"：展示模板列表。

### 9.2 场景模板选择

**功能描述**：提供 4 个内置场景模板，用户选择一个模板后进入预览。

**模板列表**：

| 模板名称 | 场景 | 列结构 | 示例卡数量 |
|---|---|---|---|
| 个人学习项目 | 学生管理课程学习、技能提升 | 待学、学习中、已学完 | 3 张 |
| 求职准备项目 | 学生管理求职准备过程 | 需求调研、方案设计、原型制作、复盘迭代 | 4 张 |
| 小团队迭代 | 小团队管理产品迭代 | 待办、进行中、待评审、已完成 | 3 张 |
| Bug 跟踪 | 开发者管理 Bug 修复流程 | 待确认、修复中、待验证、已关闭 | 3 张 |

**交互说明**：
- 模板以卡片形式展示，包含模板名称、场景描述和列结构预览。
- 点击模板卡片选中该模板，进入预览。
- 模板列表支持滚动，移动端收为单列。

**状态说明**：
- 默认态：展示 4 个模板卡片。
- 选中态：模板卡片高亮，展示"预览并创建"按钮。
- 加载中：骨架屏或 loading 动画。

### 9.3 模板预览

**功能描述**：用户选择模板后，可预览该模板的列结构、泳道和示例任务卡，确认后创建。

**交互说明**：
- 预览区展示模板的列名、列顺序和每列的示例任务卡。
- 示例任务卡展示标题、描述、负责人、优先级、截止时间等字段。
- 预览区可滚动，展示完整列结构。
- 底部展示"创建项目"按钮和"返回选择"按钮。
- 预览区展示创建后的预计效果。

**状态说明**：
- 默认态：展示完整预览内容。
- 加载中：骨架屏。
- 预览为空：模板无示例卡时展示空状态提示。

### 9.4 自动生成列结构

**功能描述**：根据用户选择的模板，自动生成看板列。

**交互说明**：
- 列名和列顺序由模板定义，用户不可在创建时修改。
- 创建后可在看板中编辑列名、增删列。
- 每个模板的列结构是固定的，不做动态生成。

### 9.5 自动生成示例任务卡

**功能描述**：每个模板默认生成 3-5 张示例任务卡，帮助用户理解任务粒度。

**交互说明**：
- 示例卡展示完整的任务字段：标题、描述、负责人、优先级、截止时间、分类、标签。
- 示例卡的字段值是预设的，用户可修改任意字段。
- 示例卡可删除，删除后不可恢复（需确认）。
- 示例卡在看板中与普通任务卡外观一致。

**示例卡设计原则**：
- 示例卡的标题应该是具体可执行的任务（如"整理作品集目录"），而不是抽象描述（如"完成作品集"）。
- 示例卡应该覆盖不同的优先级和负责人，展示字段的多样性。
- 示例卡应该是用户"第一次使用就能理解"的粒度。

### 9.6 空白项目创建

**功能描述**：保留原有空白创建路径，一键创建空项目。

**交互说明**：
- 选择"空白项目"后，只需输入项目名称和描述（可选），点击"创建项目"即可。
- 空白项目默认生成 3 列：待办、进行中、已完成。
- 空白项目不生成任何任务卡。
- 创建路径和速度与原有 Kanboard 一致，不增加任何额外步骤。

### 9.7 创建后进入看板

**功能描述**：创建成功后直接进入已生成的可用看板。

**交互说明**：
- 创建成功后，弹窗关闭，自动切换到新创建的项目。
- 看板展示模板生成的列和示例卡（或空白看板）。
- 项目列表中新增该项目。
- 无需额外刷新或跳转。

## 10. 交互与状态要求

### 10.1 默认态

- 创建向导弹窗打开，默认选中策略待验证；假设版优先展示「从模板开始」，但必须保证「空白项目」入口同屏可见。
- 展示 4 个模板卡片。
- 项目名称输入框为空，需要用户填写。

### 10.2 空白创建态

- 切换到「空白项目」后，模板区隐藏。
- 只展示项目名称和描述输入。
- "创建项目"按钮始终可用（只要项目名称非空）。

### 10.3 模板选择态

- 4 个模板卡片以网格形式展示。
- 点击模板卡片选中该模板，卡片高亮。
- 选中后展示"预览并创建"按钮。

### 10.4 模板预览态

- 展示模板的列结构和示例卡预览。
- 预览区可滚动。
- 底部展示"创建项目"和"返回选择"按钮。

### 10.5 创建成功态

- 弹窗关闭。
- 项目列表新增项目。
- 看板自动切换到新项目。
- 展示新生成的列和示例卡。

### 10.6 必填错误态

- 项目名称为空时，点击"创建项目"按钮，输入框下方展示错误提示。
- 错误提示：「请输入项目名称」。
- 输入框边框变红。
- 错误提示在用户输入后自动消失。

### 10.7 无模板匹配或模板不可用状态

- 当前版本不涉及此状态（4 个模板始终可用）。
- 如果未来模板扩展，可在此状态中处理模板加载失败的情况。

### 10.8 移动端基本要求

- 创建向导弹窗在移动端（390px 宽度）占满屏幕宽度。
- 模板卡片在移动端收为单列。
- 预览区在移动端可纵向滚动。
- 所有按钮可点击，无横向溢出。

## 11. 数据与埋点假设

> **声明**：以下埋点定义是假设版，实际埋点方案需要在真实产品开发时确定。当前静态原型无法实现真实埋点。

### 埋点事件定义

| 事件名称 | 触发时机 | 参数 | 用途 |
|---|---|---|---|
| project_create_open | 用户点击"新建项目"按钮 | source（首页/项目列表） | 统计创建入口使用频率 |
| project_create_mode_select | 用户选择创建方式 | mode（blank/template） | 统计空白创建 vs 模板创建比例 |
| project_create_template_select | 用户选择模板 | template_name | 统计各模板使用率 |
| project_create_template_preview | 用户进入模板预览 | template_name | 统计预览到创建的转化率 |
| project_create_submit | 用户点击"创建项目" | mode, template_name | 统计创建完成率 |
| project_create_success | 创建成功 | mode, template_name, task_count | 统计创建成功后的任务数 |
| project_create_fail | 创建失败 | mode, template_name, error_type | 统计创建失败原因 |
| task_example_modify | 用户修改示例卡 | template_name, task_id | 统计示例卡修改率 |
| task_example_delete | 用户删除示例卡 | template_name, task_id | 统计示例卡删除率 |

### 数据口径假设

| 指标 | 计算方式 | 备注 |
|---|---|---|
| 首次项目创建完成率 | project_create_success / project_create_open | 需要区分新用户和老用户 |
| 首次创建耗时 | project_create_submit - project_create_open | 需要客户端计时 |
| 模板使用率 | mode=template 的 project_create_submit / 总 project_create_submit | - |
| 示例卡修改率 | task_example_modify / project_create_success 中包含示例卡的项目数 | - |
| 示例卡删除率 | task_example_delete / project_create_success 中包含示例卡的项目数 | - |

## 13. 风险与待验证问题

### 风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 用户假设未经验证 | 设计方案可能偏离真实用户需求 | PD-002 研究执行后更新 PRD |
| 4 个模板可能不够 | 不同用户可能需要更多模板 | 保留 P1 模板扩展能力 |
| 示例卡设计不当 | 示例卡可能被用户直接删除，没有帮助 | PD-002 研究中观察示例卡使用行为 |
| 老用户被干扰 | 模板入口可能让老用户觉得多余 | 保留空白创建路径，不增加老用户步骤 |

### 待验证问题

| 问题 | 验证方式 | 依赖 |
|---|---|---|
| 新手面对空白项目是否真的会卡住 | PD-002 可用性测试 | PD-002 执行 |
| 模板是否真的能降低创建成本 | PD-002 路径 A vs 路径 B 对比 | PD-002 执行 |
| 示例卡是否能帮助理解任务粒度 | PD-002 观察用户是否参考示例卡 | PD-002 执行 |
| 4 个模板是否覆盖核心场景 | PD-002 访谈中确认场景匹配 | PD-002 执行 |
| 字段微文案是否有帮助 | PD-002 观察字段填写行为 | PD-002 执行 |
| 老用户空白创建是否被打扰 | PD-002 路径 C 观察 | PD-002 执行 |
